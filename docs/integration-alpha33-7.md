# 第07步：真实双端与既有 IM 隔离集成

**当前结论：真实双端／IM 只读闭环已补齐；候选原生 Desktop 容器仍未验收，不能直接正式切换。**
候选仍为 `0.33.0-alpha.7`。正式双端保持 `0.32.0-alpha.11`，DSH `0.2.1-rc.3`，
官方 IM `5.6.0`。本轮未改产品运行时代码或冻结清单，未提交、推送、发布或部署正式插件。
第二轮获准暂时正常停止正式双端，保证测试消费者独占；验收后已停止测试 Host、恢复正式双端。
下面保留首轮失败证据，不把后来补验覆盖为首轮成功。

## 环境与范围

- Mac 与真实 ECS 各一套独立官方 Web Host；独立 HOME、全局规则路径、工作区、端口和数据库。
- 自有双端通信走回环接口及 SSH 转发，没有新增公网端口；正式插件未替换。
- 使用已配置的两个正式机器人进行获准的临时切换，原账号和私聊配置不改名、不迁历史会话。
- 模型仅复用旧独立环境已获准的 DeepSeek 官方凭据；业务推理与语义解释均为 `deepseek-flash/high`。
  上游原生会话标题辅助请求使用 `off`，不能把全部模型请求都称为 high。
- 本地审批凭据仍保留在 Mac；ECS 使用配对中继访问固定平台操作，不接收该机器人密钥。
- 两端规则与 19 个全局 Skill 由真实保护性安装器写入测试 HOME，原用户规则哨兵完整保留。
- 所有代输入均为用户授权的隔离测试，不代表用户本人手打或真实业务批准。

## 消费者独占阻断

获准的切换先通过官方 `bot.disconnect` 断开正式消费者，接口当时返回已断开。
但当前官方 IM 的 `ConnectionSupervisor` 默认健康检查周期为 15 秒，
每轮执行 `controller.initialize()`；该方法会重新启动已配置但断开的机器人。
`disconnectBot()` 只关闭运行实例、保留配置，没有向该 supervisor 登记持续暂停。
因此，**一次断开回执不是持续独占的证据**，不能把它当成测试窗口的全程停机保证。

首轮发现后立即停止两套测试 Host。复核两个正式消费者已连接，正式配置哈希和自有业务表快照未变化。
首轮没有重启正式进程；这一行为可从已安装上游源码复核，不需要修改上游代码。

以下证据不计入通过：

- 后续身份确认的普通模型旁路回复，以及“发送拒绝方案”请求，测试 Host 未记录对应模型调用。
  不能把这些聊天当成独占测试环境的原生消息回归。
- “查不到任务”不能据此归因为任务名空格，也不能据此修改关键词包含查询。
  确定原因之前，不增加语义搜索、不放松唯一匹配规则。
- 首轮结束时隔离账本中的拒绝方案为 pending，尚未实际投递；当时没有可信拒绝决定。
- 正式聊天可能保留测试往来产生的新普通回复；不删除或改写这些历史消息。

定位时读取的上游文件：

- `plugin-src/host/channels/feishu/connection-supervisor.mjs`：默认周期与 initialize 调用。
- `src/channels/feishu/multi-bot-controller.mjs`：initialize 与 disconnectBot 的生命周期。

不采用删除正式机器人、清空配置、重复发送断开、修改第三方源码或强杀运行中会话来规避。
下一次复用同一机器人需要更强的独占边界：用户确认后正常停止正式 Host，再启动隔离消费者；
或者改用专用测试机器人。两个方案都要保留配置、独立回滚并持续核对消息实际归属。

## 第二轮独占补验

用户明确允许短暂停止正式双端。重新确认空闲并备份后，正常退出正式 Desktop、停止正式云端服务，
确认原消费者进程不在运行，再启动两套测试 Host。测试期间不修改正式插件、机器人配置或历史业务账本。

| 验收项 | 实际结果 | 限定 |
| --- | --- | --- |
| 持续独占 | 正式进程停止后测试接入，跨越上游健康检查周期后正式进程仍未启动 | 不以一次 disconnect 回执代替独占 |
| 真实 IM 拒绝 | 引用原方案回复“不接受，请拒绝，不要执行”，账本成为 rejected，本地私聊看到权威回执 | 授权代输入的隔离方案，不是实际业务授权 |
| 四类决定 | approved／held／changes_requested／rejected 各 1；4 条回执 sent、无错误 | 前三类来自工作台，拒绝来自真实 IM；未要求重复批准 |
| 本地入口调度云端 | 本地机器人自然语言受理一次性任务，目标端解析 ds flash，延迟 90 秒、max_runs=1 | 受理返回后本地原生会话 running=0，未等待云端完成 |
| 云端独立 worker | 独立 task-worker 会话只执行 1 批，计算 8+13=21，生成报告；attempts=1，error=null | 4 次业务请求实际使用 deepseek-official／deepseek-flash／high；另有 1 次原生标题 off 请求 |
| 云端重启恢复 | 到期前正常重启测试云端，原排队任务、到期时间、预算保留，恢复后按原计划执行 | 没有新建替代任务或追加重试 |
| 本地离线通知 | 本地测试 Host 停止期间，云端完成通知持久 queued；恢复后 accepted | 云端只有 1 条该任务结果通知，本地收件箱 attempts=1；真实本地私聊可见 |
| 真实模型报告下载 | Mac 浏览器点击下载 ECS 报告，实际落盘 511 字节，SHA-256 与成果登记完全一致 | 不只看“已交给浏览器”文案，不把零模型探针算成模型成果 |
| 失效文件 | 缺失文件按钮返回“文件已不存在 · 本次未提供文件或跳转” | 没有回退到任意路径或自动创建文件 |
| 过期快照 | 历史详情停用下载；用户手动刷新后重新核验再下载成功 | 没有关闭新鲜度门禁或恢复自动刷新 |
| 云端聊天查询 | 云端机器人按任务名查到同一模型任务，返回 1 批、模型、成果介绍和工作台入口 | 不新建、调度、审批、发文件或追加重试 |
| 重启账本保持 | 审批、决定、回执、窗口身份及用户规则摘要与重启前一致 | 预期变化仅为本次 worker 结果、通知和只读观测 |

拒绝方案最初只存在于夹具账本；第二轮通过既有幂等审批请求公开接口投递原方案，
保持原事件和原审批 ID、未增加审批记录，再从真实私聊引用它完成拒绝。
这不证明“让模型发布任意既有未投递方案”的自然语言能力已经接通。

新增模型任务是只读验收，不绑定仓库、不运行 shell、不读取用户资料、不开发或写仓库。
最终共 9 个隔离任务：原 8 个夹具加 1 个模型任务；原审批任务没有新增执行批次。
模型查询回复有个别名称旁注／按钮同义称呼不够精确，列为非阻断文案项，不据此改核心查询逻辑。

## 恢复与保留

- 两套本轮测试 Host 已正常停止，测试状态保留；没有重试旧任务、清库或伪造审批。
- 两个正式机器人均已连接；正式插件仍为 alpha32-11。
- 已备份的正式配置、全局规则、凭据哈希均与基线一致；自有业务账本逐表比较无差异。
- 正式 ECS 服务已启动，本地 Desktop 正常打开；原生 IM 面板显示本地机器人 1/1 在线。
  本地重启后旧的持久 Cookie 探针不可用，改用原生界面核验连接、公开自有 health 与只读文件／表摘要验证恢复，
  没有创建绕过认证的接口、改配置或为验收再次重启正式环境。
- 两套测试 Host、专用 SSH 转发和独立浏览器验收空间均已停止／收起；不留第二个消费者。
- 当前测试窗口身份即使仍保留在账本，也受原有效期约束；停止 Host 不扩大它的有效期。
- 私有脚本、配置、模型遥测、平台消息证据、下载件、数据库与日志仅留忽略的验收目录，不进入源码分发。

## 剩余验收

1. 候选原生 Desktop 容器验收仍未覆盖；Mac 官方 Web Host 与正式旧版 Desktop 的恢复不能替代它。
2. 正式启用前仍需核验本地统一 IM 路由迁移、旧配置兼容与回滚方案，另行获得部署确认。
3. 不把当前 macOS＋Linux Host 证据扩展为所有操作系统 GUI 已通过，也不把状态通知当成手机文件附件入口。

工作台修改／批准／暂缓已有真实账本证据，无需为“凑全通过”重复确认原方案。
