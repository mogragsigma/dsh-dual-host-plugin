# 第06步：成果入口、受控下载与对话查询

候选 `0.33.0-alpha.7`。仅隔离验收，不代表正式部署或发布。
主入口保持工作台的具体任务，IM／DSH 对话用于辅助查询；本轮不新增审批或开发权限。

## 用户操作

### 下载报告

进入「大肥鱼bot → 任务与状态」，按名称选择任务，查看「成果物」中的介绍。
非仓库报告可点击「下载文件」，也保留「查看执行会话」。页面过期先手动刷新。
下载前重新核验任务／批次、修订、文件归属、权限、存在性、大小和 SHA-256；浏览器再核对字节摘要。
只在明确点击时请求文件，不轮询、不自动下载。提示“已交给浏览器保存”不冒充磁盘落盘证明。

Gitee 既有文件和已完成交付仍提供**固定版本页面**，不镜像仓库、不生成任意下载链接。
外部页面由用户自己的登录独立鉴权；没有仓库的任务不需要绑定 Gitee。

### 在对话中查询

可直接询问本地／云端 DSH 或已经接入的机器人：

> 资料整理这个任务进展如何？有哪些成果，需要我处理什么？

`task_results` 使用部分任务名称的连续包含匹配；不增加语义搜索或错字纠正。
唯一匹配才读取详情，多项则先请用户区分，不默认取第一项，不要求用户记编号。
读取权威快照、批次、审批和成果登记；不依赖某个固定 DSH session，不创建或重试任务。
需要打开具体成果时，`task_artifact_access` 再核验页面／执行会话。

工作台的「在对话中查询」可展开并复制完整提问，由用户选择已有对话粘贴。
它不会抢占任意主会话、自动插入消息或自动发送；审批继续使用任务内可信入口。
查询不等于把文件发到 IM；明确要求发送文件时，仍由既有通知工具核验收件目标与授权。

## 模块与安全边界

| 模块 | 改动 |
| --- | --- |
| `task-results.js` | 复用只读 board 查询，提供跨 session 的名称定位、歧义候选、进度／审批／成果快照 |
| `native-tools.js` | 增加 `task_results`、`task_artifact_access`；不提供模型下载字节工具 |
| `task-artifacts.js` | 独立 `artifact_download` 方法，仅接受成果标识、当前修订和预期摘要；原访问方法不扩成任意路径读取 |
| `link-contract.js` | 独立 `task_results:1`、`artifact_download:1` 能力；旧端不支持则拒绝，不退回旧下载路径 |
| `diagnostics.js` | 查询与成果核验归入快照回执，不能推导执行或已读 |
| `artifact-download-client.mjs` | 校验响应身份、长度和摘要，使用 attachment Blob，回收对象 URL，不持久保存字节 |
| `workbench-client.js` | 真实下载、明确错误、折叠提问辅助入口；保持手动刷新及蓝白样式 |
| 全局规则托管模板、原生上下文与 Skill | 查询、下载、IM 发送及审批边界分别说明；不修改用户实际规则文件 |

下载边界：

- 只允许当前修订、所属批次持久完成的 `report`，上限 256 KiB；沿用现有登记格式，不增加任意文件导入。
- 自有回环 API 由官方 Host 鉴权，下载额外核对 Origin 与当前 Host；双端调用走配对、角色、命名空间及能力协商。
- 这是已认证 Host 的成果读取，不是批准人身份认证，也不是新增跨用户 ACL／操作系统隔离；不注册通行密钥。
- 文件安全沿用目录归属、权限、文件类型、inode、单硬链接、无符号链接、前后 stat 与摘要检查。
- 记录或文件被替换、修订过期、运行失败、权限变化、离线／不兼容均拒绝，不以另一任务或文件代替。
- 不提供公网链接、下载票据、路径参数或登录令牌；响应 `no-store`／`nosniff`，文件只经私有 RPC 返回当前浏览器。
- 不修改任务、审批、执行预算、仓库、通知目标；下载不能授权开发、提交、推送或发布。

实际浏览器发现并修复：原成果错误只有 `code`，不满足官方 RPC 的 failure 格式。
现在补齐固定 `message` 和空 `details`，页面能正确显示“文件已不存在”等原因，不泄漏底层错误正文。

### 界面核对

| Before | After | Why |
| --- | --- | --- |
| 下载按钮没有正式接线 | 明确点击、双端核验、浏览器摘要核对后保存 | 不用模拟文件冒充真实成果 |
| 失效文件显示 RPC 技术错误 | 原生格式回执与明确不可访问原因 | 用户知道为何不能下载 |
| 必须自行记住如何提问 | 当前任务内折叠的可复制问题 | 保留明确任务上下文，不占用主会话 |
| 查询状态与成果工具分散 | 一次名称查询，歧义再澄清 | 不让用户填写内部编号 |

## 回归证据

定向自动化覆盖：下载归属、修订、成功批次、大小、哈希、缺失、替换、权限、软／硬链接，
同源限制、旧端能力、浏览器防重复与迟到响应、查询歧义／分页、跨 session、原审批／通知及规则保护。
41 份具名安全测试共 **692 项：691 通过、1 项历史跳过、0 失败**。
不是所有历史测试，没有通配运行 Git 写入用例。

本轮两套全新官方 DSH `0.2.1-rc.3` **Web Host 均位于本机**，分别承担 local／cloud 角色。
使用独立 HOME、配置、状态、端口及自有插件副本，不加载日常配置、模型凭据或机器人凭据。
原生 standard／ptc／cordis／minimal 模式分别加载 87／87／90／3 个工具；新增两项查询工具，没有替换模式。
官方工具运行时在两端的不同原生会话中执行唯一查询与同名查询，均返回正确结果。
报告来自实际独立 worker 生命周期中的零模型探针；不是模型生成质量验收。

本地入口和模拟云端入口均经浏览器实际下载同一份 119 字节报告，两个下载件与云端登记的大小及摘要一致。
真实页面显示缺失文件的明确原因，不再出现 RPC 格式错误；模拟云端还成功打开所属只读 worker 会话。
双 Host 重启前后，任务、成果、审批、处理账本、job／run、预算和用户规则哨兵逐表保持，没有新增任务或重试。
跨会话查询在重启后继续通过，模型请求为零。
900px 窄屏及宽屏核对通过，下载按钮与提问输入框无重叠／越界。验收结束后已停止本轮两套测试 Host 并关闭验收空间。
Gitee 只读固定提交及权限失效在受控 API 夹具回归，不使用浏览器执行 Gitee 操作。
所有原始日志、状态库、下载件和测试凭据仅留私有目录，不进入源码导出。

## 限制与下一步

- 本轮不证明真实 ECS、原生 Desktop 容器、Windows 或手机浏览器下载兼容性。
- 没有调用真实模型，也没有向真实 IM 发送查询消息；原生工具可跨 session 调用不等于自然语言端到端已实测。
- Gitee 已有的实时只读访问链路不变，本轮未再次访问真实私有仓库，也不 commit／push。
- 主对话辅助是用户自主复制／粘贴，不新增固定会话或主动推送会话消息。
- 第07步统一完整隔离回归，补齐真实 IM／模型及目标端验证，再单独确认正式切换；市场发布仍暂停。
