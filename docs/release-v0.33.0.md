## 版本与范围

按用户授权将 `v0.33.0-alpha.9` 晋级为源码正式版 **v0.33.0**，仅向 A 线 `dsh-dual-host-plugin` 同步。
B 线 `dsh-cloud-tasks` 不读写，不变更可见性，不复制私钥。

相对已验收 alpha.9，bundle 只有四个元数据文件改变：

| 文件 | 差异 |
| --- | --- |
| `package.json` | version 去除 alpha.9 后缀，description 改为中性能力说明 |
| `package-lock.json` | 顶层及根包 version 与 package.json 一致；依赖不变 |
| `compatibility.json` | version 一致；不扩大声明或授权 |
| `link-contract.js` | 导出的插件 VERSION 一致；协议与能力字段不变 |

其余 255 文件字节不变，包括核心实现、20 个 Skill、全局规则和 UI。
新的 `source-bundle-v0.33.0.json` 保存完整 259 文件摘要；旧 alpha.9 冻结证据不改写。
版本号“正式版”不等于已上架市场，不构成对未验平台／新版 Host 的兼容承诺。

正式 Mac Desktop／ECS 仍运行 alpha.9。本次不重启、不改线上配置、不部署版本标签，不重试任何旧任务。
真实生产部署、IM、成果下载与回滚验收继续以 [alpha.9 部署记录](desktop-deployment-alpha33-9.md) 为准。

## 本版能力与边界

- 工作台以成果物和待处理事项为核心；已登记报告可受控下载，Gitee 成果跳转固定版本页面。
- 工作台为主要人工介入入口，本地已绑定 IM 私聊为辅助身份确认、方案与权威回执入口。
- 支持自然语言批准、拒绝、暂缓及修改意见；有条件同意不能执行旧方案。身份复用不注册新账号或通行密钥。
- 异常核对、补充意见、建议和结束范围有明确入口；查看状态或建议不授予执行权，不重置旧预算。
- 正式仓库代码、任务开发、commit、push、发布分别授权；插件规则和 Skill 不代替持久门禁。
- 官方 DSH／IM 源码不修改；复用公开 owner 鉴权、credentials 服务与官方 IM 接口。
- 当前真实环境证据为 macOS＋Linux ECS；Windows 仅部分路径和契约测试，不宣称 Windows 真机全链路通过。

| 检查 | 本次结果 |

| 介入／审批／下载／市场包声明／版本晋级 | Mac 隔离 HOME：749 项，748 通过、0 失败、1 历史跳过 |

| npm 打包预览 | 258 文件、6,511,468 字节；npm 默认不打包 package-lock.json；未写归档或发布 |
| 模块索引 | 由当前源码重新生成，静态依赖不冒称完整动态依赖图 |
| 生产部署与真人 IM | 沿用已完成的 alpha.9／第07步分层证据；不冒称本次又执行一次 |

首轮新增包声明测试发现 YAML 测试解析器依赖未显式声明，并非产品逻辑失败。
修复在 `tests/package.json`／锁文件增加固定 YAML 测试依赖，并从测试目录解析；未给运行包增加依赖。
随后修正测试夹具的 package.json 读取路径（产品声明仍从 bundle 读取）；两次失败日志保存在私有验收目录，
不上传、不掩盖；10 项定向复核已通过，完整重跑结果以表中最终值为准。

复现方式见 README。`run-intervention-regression.py` 固定 45 个已审查文件；
`run-onboarding-regression.py` 固定 13 个安全导览文件。使用临时 HOME，不加载日常 DSH 会话和机器人。
不通配执行历史测试；旧 S65“仅 UI 可变”的断言明确跳过，正式版完整性由新摘要与元数据等价性测试验证。

## 源码上传与凭据保护

只上传本项目插件、规则托管模板、Skill、UI 源、合成测试、构建脚本和去敏文档。
不上传 private、运行时目录、数据库、日志、会话、真实测试截图、机器人配置、API Key、SSH 私钥或依赖安装目录。

- 工作区与 `--index` 源码审计分别执行，包含二进制检查；合成负例按文件哈希批准，不豁免整个测试目录。
- `SOURCE-MANIFEST.json` 列出本次待提交源码摘要，排除自身，避免自引用。
- Git CLI／SSH 仅快进推送 A 仓库，回读远端 main 与版本标签验证；不强推、不重写历史。
- 源码审计是多层防护，不承诺能数学证明所有未知形式的敏感数据均不存在。
- 没有 npm publish、市场索引发布、仓库公开化或生产重部署。包的 `private: true` 保留。

## 维护接续与回滚

源码同步完成后进入市场发布研究，而非直接上架。下一步核对官方分发方式、包名与入口、元信息、许可证、
图像素材使用权、兼容声明及清洁安装／升级／卸载证据，再提出最小发布计划。

当前包名仍是本地开发作用域；正式分发名称、发布账号和授权范围须独立确定。
不能因“正式版”而去掉安装确认、身份核验、审批或业务写入门禁。

当前不需要生产回滚：线上未变。若之后正式安装 v0.33.0，仍须按已记录的托管归属维护与回滚步骤进行。
已有新决定或身份记录时，不得用旧整库覆盖；详见 `desktop-migration-alpha33-8.md`。
