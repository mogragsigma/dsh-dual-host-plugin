# 原生 Desktop 验收与审批路由迁移

## 本轮变更

- 本地工作台为主要介入入口；本地 IM 的固定已绑定私聊为身份核验、方案及权威回执的辅助入口。不要求同一个 DSH session，不要求通行密钥或新账号。
- 原生 Desktop 的官方代理移除 HTTP Origin。仅在服务端识别到官方 Electron Node Host 且目标为本 Host 精确回环端口时接受缺少 Origin 的请求；仍经过官方 owner 会话鉴权。Web 不享有此例外。
- 本地 IM 直接适配器通过官方 `credentials.resolve` 读取明确凭据引用；每次操作重新解析，撤销或轮换使缓存平台令牌失效。凭据不复制到云端，不修改 IM 源码，不新增消息消费者。
- 任务、成果、审批和异常处理的其余候选能力见 alpha.3—alpha.7 分步验收。自动发布未实现／未启用，旧授权不因升级扩展。

## 隔离验收证据

1. 官方原生 Desktop 使用独立 HOME、DSH_HOME、DSH_AGENTS_HOME、Electron user-data-dir 启动，不复制日常会话或机器人；云端角色采用合成平台适配器。
2. 实际 `dsh-app://app/` 窗口中完成批准、拒绝、暂缓及“同意，但请把报告改成两段”。分别写入 approve、reject、hold、amend；窗口身份经合成平台证据核验，未当作真人飞书实测。
3. 关闭、重启后四类决定各保留一份；零模型调用，零 worker，零仓库写入。
4. 实际 HTTP：无 owner Cookie 返回 401；外站 Origin 返回 403；合法原生容器请求通过；Web 缺少 Origin 仍拒绝。
5. 官方 credentials 服务解析隔离引用成功，测试值不是真实密钥。标准、PTC、Cordis、minimal 四种原生预设均可加载。
6. 真实飞书证据沿用第07步的独占消费者验收，不把本轮合成平台测试重复计作真人验收。

## 存量迁移核对

- 只读复制正式数据后离线构造候选，不启动服务、调度、模型或 IM 网络。历史 38 个任务、21 个 job、32 个 run、13 份方案及 10 条决定均保留。
- 13 份历史方案均已过期或处于终态；没有仍有效的待决定／已批准方案。旧方案投递均 inactive，10 条旧回执均 sent。部署前必须再次核验，不依赖这份文档的历史计数。
- 旧运行状态为 completed、cancelled、needs_review、waiting_capability；不重置预算、不重试、不把 waiting_capability 改成 pending。
- 审批迁移新增本地私聊绑定，禁用旧云端绑定；历史记录不改写。原有通知默认值和历史任务目的地不强制改写。本地辅助路由是一个新增的显式可用目标，不偷偷切换旧定时通知。
- 已验证本地机器人 app、bot、owner 与前轮绑定相同，官方平台核验目标确为私聊。旧 legacy 通知可能指向群，与新审批私聊不同；不能从旧群地址推断审批目标。
- 副本迁移仅改变旧表 `approval_chat_bindings`、`approval_guidance_epoch`；新增工作台表。副本恢复旧备份后，原审批查询与原 cloud 绑定恢复，调度没有启动。
- 规则使用自有保护性安装／维护模块升级，保留用户前缀、后缀和未知 Skill 文件。隔离演练：20 文件安装、6 文件升级、6 文件回退，用户原文逐字保留。

## 正式切换流程

1. 再核验双端空闲、无待发送方案、无有效旧批准；核验正式配置与计划摘要一致。
2. 正常退出 Desktop，停止云端服务。备份原 profile、凭据文件、全局规则、托管清单、Skills、原生会话及自有持久状态；备份仅保存在私有目录。
3. 安装独立版本目录，保留旧目录及依赖；只替换自有入口路径和明确的 `chatApproval → localApproval` 配置，不重写第三方配置段。
4. 在 Host 停止时通过自有维护模块升级托管规则／Skill，再核对用户非托管内容摘要。
5. 启动双端；先核验版本、历史业务行、原生 IM 在线、审批中继、工作台和侧栏，再进行限定的验收交互。不给旧任务新授权。

## 风险及回滚

| 风险 | 处理 |
| --- | --- |
| 旧批准仍有效，迁移会撤销其身份 | 部署前阻止切换，单独核对，不静默重签 |
| 已禁用旧绑定直接切回会触发再激活保护 | 不只改旧配置后强行启动；先按以下回滚层次处理 |
| 切换前已有排队／未知发送 | 保留状态，停止切换，不重放 |
| 本地离线 | 审批中继等待，不回退到云端机器人或猜测用户身份 |
| 官方 Desktop 行为升级 | 缺少已验证容器证据则拒绝审批；重新做原生容器验收 |
| 正式服务停机最后一刻收到原生输入 | 可能中止；正常停机前重复空闲检查，原生消息不自动重放 |

**接流量前的完整回滚：**双端停机，确认没有新业务行，再恢复本轮备份的自有状态、原 profile 与配置；规则通过旧版本维护模块保护性回退。隔离副本已演练。不能仅重新启用旧 disabled 绑定来假称无损回滚。

**接流量后的保守回滚：**先停止服务并保存新的数据库／会话／操作回执；禁止用旧整库覆盖新决定。必要时恢复旧 UI／查询能力但保持审批与执行停用，逐项核对新决定与新绑定；不能宣称旧版本能识别新的工作台身份证明。需要恢复旧审批路由时另做受控迁移，不自动删除新记录或重签方案。

当前阶段不执行 Gitee commit、push、发布或市场上架。
