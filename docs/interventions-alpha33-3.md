# 第02步：持久介入事项

候选版本 `0.33.0-alpha.3`。本轮完成**持久事项、分类、来源观测历史和工作台读取接线**，
不是实际审批或异常恢复闭环。未正式部署、发布、提交或推送；未访问日常配置、凭据或生产 ECS。

## 用户可见变化

| 原来 | 本轮 | 原因 |
| --- | --- | --- |
| 待处理由每次详情临时拼出 | 按任务、来源记录与修订持久定位，展示处理记录 | 切换会话、页面或重启不丢失已登记事项 |
| 黄色状态易被理解为都等用户批准 | 区分“需要你决定”“需要先核对”“需要维护处理” | 缺报告、能力不足或发送未知不能靠再批准解决 |
| 只有状态或错误 | 原因、下一步、处理后的影响；补充问题直接展示 | 说明谁应处理以及哪些操作不会发生 |
| 来源暂时不在查询窗口 | 保留“本次未核实”，不当作已解决 | 有界查询和暂时缺失不构成完成证据 |
| 旧方案可能留在缓存 | 过期、旧修订、缺少原方案只可核对 | 不呈现不再适用的决定入口 |

维持浅蓝白、既有角色点缀、紧凑内联提示及折叠历史。未新增动画或自动刷新。
“资料分析与整理”的阻塞事项显示先核对原因、已有成果和授权；**本轮尚不会自动核对或执行处理建议**。
按钮只查询说明／诊断。方案输入仍标为“尚未提交”，输入草稿不是已记账意见。

## 接口与模块

| 位置 | 职责 |
| --- | --- |
| `bundle/intervention-state.js` | 从既有去敏任务详情提取原因、责任方、候选选择与状态事实；纯计算 |
| `bundle/task-interventions.js` | 云端自有 SQLite 观测表、稳定标识、版本及追加事件；不控制业务状态 |
| `bundle/task-board.js` | 新增 `board_interventions({task_id})`；重新读取原来源后登记观测 |
| `bundle/link-contract.js` | `task_interventions:1` 能力协商，旧端缺能力即明确拒绝 |
| `ui-source/task-focus.mjs` | 事项展示投影；重新检查当前方案，不凭观测缓存开放批准 |
| `ui-source/task-focus-view.js` | 原因、责任与影响、补充问题、折叠处理历史 |
| `ui-source/workbench-client.js` | 实际详情选择／手动刷新调用新观测接口；不添加定时请求 |
| `bundle/skills/task-sidebar/SKILL.md` | 用户指引、观测与授权边界、当前尚未接入的动作 |
| `bundle/global-rules/AGENTS.md` | 紧凑路由与观测规则；未安装覆盖用户文件 |

本地入口 → 原 Host RPC → 自有配对链路 → 云端详情读取 → 云端观测账本 → 同一工作台组件。
不增加第二个 IM 消费者，不经 Gitee，同一个 IM 窗口无需固定内部 DSH session。

`board_list` 与 `board_detail` 继续只读，不回填或迁移旧任务。
新接口只接受 `task_id`；不接受客户端状态、批准人、意见、源快照或处理结果。
用户意见和结果只能从**既有审批账本的去敏读取**形成观测，不能据此生成新决定。

### 数据与一致性

自有协调器数据库增建三张表，不修改旧业务行：

- `task_interventions`：任务、来源类型／编号／修订、当前分类与状态、原因、选项、意见、结果、观测时刻。
- `task_intervention_events`：每次变化的追加快照；内容未变化时不重复增加版本／事件。
- `task_intervention_observations`：上次显式读取的时间与任务修订；未初始化不伪装空待办。

事项标识与会话无关；批准人身份并不因此绑定或放宽。
记录状态为 open、unverified、resolved、inactive、expired、superseded，均为**观测生命周期**，不替代业务状态机。
批准已记账不等于执行；拒绝方案不等于取消整个任务；来源离开待处理不等于任务完成。
有条件同意保留原文，显示需修改，不能执行旧方案。

读取原任务修订与落账时不一致则拒绝记录，提示刷新；不同来源之间不宣称跨数据库原子快照。
来源窗口暂缺时保留旧事项为 unverified，保留最后真实读取时间；重新出现时恢复观测，不重置预算。
既有详情仍采用有界来源窗口；本轮不会追溯补采所有历史变化，也不建立后台监听。
每次最多展示100事项、每项最近20事件，有更多记录时明确提示。更早已登记事件仍在数据库中。

### 迁移与回退

- 仅新增自有表与索引，安装后首次读取才采集事项；不重试旧任务，不创建审批或 worker。
- 旧客户端继续使用原详情；新客户端到无能力旧端明确报不兼容，不降级成业务控制接口。
- 回退旧自有包时保留新增表及事件，不删库；它们不是执行队列，不会被旧调度器重放。
- 正式切换仍需另行确认与备份。本轮两套全新本机隔离官方 Host 已完成重启保留验证。

## 验收证据与边界

- 定向安全测试覆盖事项持久化、同名不同任务、修订变化、来源暂缺、重启、意见与结果、无重复事件、能力协商、非法参数、只读原接口和前端显示。
- 使用官方 DSH `0.2.1-rc.3` 启动两套全新隔离 Host，分别承担 local/cloud；两者均在 Mac，不是生产 ECS，也不是原生 Desktop 容器验收。
- 合成任务通过真实自有网关及官方浏览器工作台读取；异常情景为合成阻塞，不冒称真实模型失败。
- 重启前后任务、修订、审批、身份表和介入事项／事件逐行保持；重复读取不增加事件，原用户规则哨兵保留。
- 两端原生 standard／ptc／cordis／minimal 预设分别加载85／85／88／3工具；未调用模型、未配置真实 IM 或仓库。
- 真实浏览器已核验本地经配对读取、云端直接读取、诊断／历史展开、输入草稿切任务保留及不会提交决定；窄屏单栏另行检查。
- 全局规则保持紧凑，不扩大安装器上限，不截断用户规则；49,152字节原用户规则保护用例保留。
- 全量历史测试、真实 IM 本人批准、跨操作系统和生产环境本轮未执行，不能用本报告代替。

最终定向回归：**460项，459通过、0失败、1历史跳过**。跳过项为冻结S65仅UI边界，
不适用于新增运行时模块；原冻结清单不覆盖，新候选清单为 `candidate-bundle-alpha33-3.json`。
其中新增事项核心32项、渲染5项，另补8项前端状态选择保护；不与总数重复相加。
两端未认证 HTTP 请求均返回401。实际浏览器填入的意见没有生成审批决定；隔离账本保留3事项、3事件，
重复读取与重启没有增加事件。900px双列及640px单列无水平溢出，截图已检查。
最终测试包逐文件与源码一致，两套测试 Host 均已停止，专用浏览器空间已关闭。
私有测试数据库、端口、身份材料与截图不进入源码导出。

## 接续

1. 第03步接工作台真实输入／点击、解释核对、既有可信身份复用和最终审批账本；必要时已绑定 IM 确认，不注册新身份。
2. 第04步接本地机器人统一通知、确认和回执，独立于内部会话。
3. 第05步再将异常核对、建议、修改、继续／结束接入受控动作；不能把本轮选项描述当成可调用动作。
4. 第06—07步为成果／受控下载／对话查询、隔离集成验收与部署前确认。
