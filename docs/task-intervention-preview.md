## 用户流程

点击「资料分析与整理」后，可完整演练：

1. **系统核对**：说明没有完整报告，先检查已有资料、批次停止证据和原授权。
   不再将核对工作直接标成需要用户批准。
2. **提出建议**：点击查看模拟核对结果，展示保留资料、仅补报告的建议。
   原次数 1/1 已用完；新增一次生成属于新建议，不重置原预算。
3. **输入意见**：可输入“只用已有资料，不重新检索，报告分成两段”。
   更新建议后仍需单独确认。输入未提交时直接点击继续，也会先更新建议，不丢弃条件。
4. **继续分支**：同意当前建议 → 已受理待执行 → 查看进展 → 模拟执行 → 查看处理结果。
   上方成果区出现合成报告，待办转为处理结果；未将受理直接当成完成。
5. **结束分支**：不再继续 → 核对终止范围并确认 → 模拟在途核对 → 查看结束结果。
   保留已有资料与失败历史，不把结束显示成成功；确认前可返回。
6. **稍后决定**：保留建议和意见，回来继续决定或结束，不宣称 worker 批次已经暂停。

模拟进度由明确的查看按钮推进，没有定时刷新或后台真实工作。
页面重载／重置演示清除合成状态；同一次页面生命周期中，任务切换保留未提交草稿。
审批草稿按任务、方案与修订分别保存，不能沿用到新方案。

## 待处理状态的出口

| 状态／情景 | 谁处理 | 预览出口 |
| --- | --- | --- |
| 报告缺失，系统核对 | 系统 | 查看核对结果，再决定继续、修订、暂缓或结束 |
| 待补充范围 | 用户 | 输入必填信息 → 建议 → 单独确认，或结束 |
| 有条件同意／方案修订 | 用户 | 输入修改要求 → 新建议 → 同意修订；旧方案不执行 |
| 原有批准／拒绝／暂缓／澄清 | 用户 | 沿用第一版模拟表单，批准后若缺能力转配置处理，拒绝退出待办 |
| 执行配置缺项 | 维护端 | 查看配置要求、提交模拟维护、查看维护进展，再形成处理建议 |
| 原记录不足／结果未知 | 维护端 | 不显示直接重试；提交维护请求，核对后形成新建议或结束 |
| 通知发送结果未知 | 用户／维护端 | 已看到则记录用户陈述；未看到转维护核对；不重发 |
| 不再追踪通知 | 用户 | 仅结束该通知的人工跟进，不取消任务、不改变成果 |
| 已受理／模拟执行中 | 系统 | 查看下一阶段结果，或先核对在途状态再结束 |
| 完成／结束 | 无新的待办 | 查看成果或处理记录，选择其他任务；不是重新执行入口 |

“每种状态有出口”限定当前预览情景，不代表生产中所有历史异常已能自动解决。
未知或无权处理的真实状态仍应按原可信核对路径处理，不能用模拟维护结果放行。

| Before | After | Why |
| --- | --- | --- |
| 异常只提供查看原因和提示式讨论入口 | 任务内给出核对、建议、意见及处理结果 | 用户可走完流程，不必猜如何介入 |
| 所有问题都显示待你处理 | 系统处理、用户决定与维护处理分别显示 | 明确责任，不要求用户盲目批准 |
| 输入后可能直接沿用旧建议 | 有内容时继续变为“更新建议后再确认” | 条件不丢失，不擅自执行 |
| 任务切换丢失审批草稿 | 内存草稿按任务／方案／修订保存 | 防止误操作和重复输入，不写入用户配置 |

## 实现边界

- `ui-source/preview/attention-flow.mjs`：纯合成流程、可用动作与状态文案；无网络、存储或模型依赖。
- `ui-source/preview/InterventionPanel.jsx`：任务内输入、按钮、阶段和处理记录；快照过期时保留输入并关闭提交。
- `ui-source/preview/intervention-preview.css`：只随独立预览输出；保持既有浅蓝白、角色点缀与窄屏换行。
- `ui-source/preview/task-focus-preview.jsx`：挂接合成流程及合成报告，不读取真实 Host 配置或私有数据。
- `ui-source/workbench-client.js`：新增可选预览渲染位置；真实 Host 调用方不传入，仍采用原只读回退。
- `ui-source/task-focus-view.js`：支持适配器提供内存审批草稿缓存；真实适配器与真实审批仍未启用。
- `bundle/global-rules/AGENTS.md` 与 `bundle/skills/task-sidebar/SKILL.md`：只更新自有模板的模拟边界说明。

不改变真实任务状态定义。预览可以把展示状态更新为系统核对／维护接手，但这不是后台状态迁移。
历史失败数据仍保留在诊断中，本次处理记录单独说明如何结案，不能作为真实结案凭据。
没有修改生成产物之外的后台 JavaScript 文件；原生 DSH 与第三方源码不在本轮写入范围。

通知已看到／未看到／仅结束跟进、未知记录维护；重复点击不多推进，历史和诊断可打开。

自动化重点包括：

- 主流程完整继续、结束确认和在途核对、修改要求不被继续按钮丢弃。
- 每类可达非终止模拟状态都存在到明确终点的路径；这不代替真实系统故障恢复验收。
- 稍后决定、补充输入、维护、通知已看到／未看到及只结束通知跟进。
- 旧版本提交、非法动作、超长文本拒绝且原数据不变；处理历史保留当时的建议版本。
- 审批草稿切换保留，新任务／新修订不沿用；旧 UI、成果和账本只读契约不退化。

用户确认本预览后再推进第 02 步跨平台可信工作台审批。
新增真实恢复、终止或结案能力仍归第 03 步，先说明具体动作、影响与门禁方案，不从本预览直接启用。
