# 第03步：工作台决定与既有 IM 身份复用

候选 `0.33.0-alpha.4`。工作台输入／点击、解释核对、既有 IM 窗口身份、
最终审批账本与回执已接线并通过隔离回归。**不等于真实飞书本人验收或正式上线**。
本次真实浏览器及两套官方 Host 在本机隔离运行，身份平台适配器使用合成消息。
不使用日常配置、凭据或生产 ECS；未提交、推送、正式部署或发布。

## 用户操作

1. 在本地「大肥鱼bot」选择具体任务，查看「待你处理」中的当前方案。
2. 输入“就按这个方案执行”“不批准”“先等等”或“可以，但报告改成两段”。
   也可点击同意／暂缓／拒绝；有输入时始终以完整输入为准。
3. 点击“核对我的意见”，查看系统理解、原文及绑定的完整方案。
   这一步不会写审批决定，也不执行任务。
4. 当前窗口没有身份时，点击“通过已绑定 IM 确认身份”。
   在原有审批私聊核对窗口校验，回复专用身份消息，然后回工作台点“我已回复，核对身份”。
   **身份确认不是任务批准**，不新增账户，不注册通行密钥。
5. 点击“保存这次决定”，在同一任务区域看到云端审批账本结果。
   同一窗口10分钟内可逐项处理其他方案，不反复跳 IM，但每份方案都须用户核对并保存。

| Before | After | Why |
| --- | --- | --- |
| 输入只查询接线说明 | 输入→核对解释与完整方案→保存决定 | 用户知道何时仅准备、何时真正记账 |
| 新增设备身份注册 | 明示复用既有 IM 身份，短时绑定当前窗口 | 不绑定 Mac，不增加账户或通行密钥 |
| 输入后点击快捷按钮可能令人担心条件丢失 | 完整输入优先，条件同意显示修改重审 | 不把修改意见拆成旧方案批准 |
| 超时可能诱导重复批准 | 保留原操作，只查结果；明确未收到准备时才允许手动重开 | 未知保存不能转成第二次批准 |
| 宽屏可读、窄屏按钮可能拥挤 | 内联身份区域、按钮换行、保留8px间距 | 640px无水平溢出，保持浅蓝白与既有角色 |

批准仅记账；拒绝方案不等于取消整个任务；暂缓决定不等于暂停在途 worker。
有条件同意进入 `changes_requested` 并保留完整原文，必须修订、重审，不能执行旧方案。
异常核对、解除阻塞和结束任务不是本步骤能力，不使用“批准”按钮代替。
不定时刷新、不自动发送身份消息、不增加占位介绍面板。

## 可信身份与边界

- 当前暂用**已有云端可信审批私聊绑定**；第04步才统一本地机器人通知、确认与回执。
  UI明确这一过渡状态，不能把“通知已送达”当成“身份已绑定”。
- 绑定包含机器人应用、机器人身份、私聊、批准人。单独 App ID、昵称、Host 登录、
  配对令牌、模型文本或内部 DSH session 都不证明批准人身份。
- 浏览器使用256位随机窗口能力，只有内存保存；服务端保存节点绑定摘要。
  刷新／关闭页面不继承该能力，不写本地存储、模型上下文或日志。
- 平台消息明确允许该窗口10分钟内记录用户逐项确认的决定。
  原提示与本人回复通过现有官方消息适配器独立回读，检查发送方、私聊、引用、时间、未编辑与原文。
  后续矛盾回复、绑定变化、编辑、过期、不可读或关闭窗口身份均阻止新的保存。
- 每次保存重新检查平台证据及当前方案／任务修订／原决定；不是“一次确认永久登录”。
  同时准备的旧意见不能覆盖后来已记账的决定。
- 停止窗口身份不撤销独立的历史方案决定；改变原决定需按当前方案另行处理。
- 原生 HTTP 的身份与来源检查保留，自有交互路由额外校验 Origin 与已验证 Host。
  目标缺少安全随机数时只禁止审批，不阻止整个工作台挂载或原生导航。
- 此边界不能隔离可改插件／数据库的管理员，也不解决同源恶意代码攻击；不宣称系统级身份隔离。
- 没有自动选机器人、扩权、解锁、启动 worker、Git 操作或发布。

## 模块与协议

| 模块 | 职责 |
| --- | --- |
| `ui-source/approval-workbench-client.mjs` | 内存窗口能力、准备／查询／保存、原事件重用、未知结果保护 |
| `ui-source/task-focus-view.js` | 完整输入、解释与方案核对、身份状态、明确保存入口和账本结果 |
| `bundle/workbench-host.js` | 原生授权 HTTP 路由、来源检查，转给自有配对 RPC |
| `bundle/link-contract.js` | 独立 `approval_interaction:1` 协商，缺能力不降级 |
| `bundle/workbench-im-identity.js` | 既有 IM 消息确认、10分钟窗口、原消息回读与失效检查 |
| `bundle/workbench-decisions.js` | 有界语义解释、不可变准备单、幂等保存、身份凭证与决定同事务 |
| `bundle/approval-ledger.js` | 复用原状态机；新增工作台 IM 来源证明、意见投影及绑定有效性 |
| `bundle/index.js` | 云端实例、配对路由、维护活动跟踪与关闭 |
| 全局模板与 `task-approval`／`task-sidebar`／`task-direct-link` | 用户指引、授权边界、过渡入口说明；不安装覆盖用户规则 |

链路：本地工作台 → 原 Host 认证接口 → 自有配对 RPC → 云端解释／既有 IM 证据 →
原审批账本事务 → 原工作台查询回执。**不经过 Gitee，不增加第二个 IM 长连接消费者**。

新方法：`approval_interaction_describe/prepare/status/confirm/identity_send/identity_check/identity_close`。
`prepare`只接受任务、方案、修订、全文及窗口／操作引用；`confirm`只接受窗口／操作引用。
不接受客户端提供的 action、principal、approved 或解释结果。模型工具不暴露这些浏览器能力。
旧 `approval_workbench:2` 继续只读说明，退役身份方法仍拒绝；旧说明不代表新协议已启用。

新增三表均在云端自有协调器数据库：

- `workbench_decision_operations`：准备单、原文、解释、方案状态摘要、有效期与最终决定引用。
- `workbench_im_sessions`：窗口摘要、节点、既有绑定摘要、平台提示／回复与状态。
- `workbench_im_proofs`：本次方案、解释、原文及已核验平台证据，与原决定在同一事务保存。

准备状态 `processing → ready → recorded`；中断为 `needs_review`，方案变化或到期返回不可保存。
语义解释并发最多4个，采用现有有界无工具分类器；规则可确定的常用句不需要模型。
条件同意不会因模型失败变成批准，仍以修改意见处理；歧义保持待澄清。
窗口身份发送也限定最多4个在途；维护拒绝不留下孤立的在途行。

账本回执会在工作台直接显示。已有方案投递记录时沿用原 IM 回执意图；
没有原方案投递记录时不猜收件人。统一本地机器人送达证明属于第04步。

## 迁移与恢复

- 只增自有表和证明类型，不重解历史消息、重置预算、修改旧批准或重试旧任务。
- 重启将未完成解释／身份发送置为待核对，不自动请求模型或再发消息。
- 保存和结果未知只查原操作。准备确实未入库、且从未发送保存时，有“返回修改意见”出口；
  一旦保存尝试过，无法查到操作也不能自动重新批准。
- 浏览器仅在当前页面内保留草稿；刷新后未提交文本不保证保留。
  服务端已保存的准备单、原意见与决定保留，但不向新窗口泄露旧窗口能力。
- 回退包必须保留新增表，不能清库消除未知状态。旧版本不认识 `workbench-im:` 证明，
  可能将新批准视为 `identity_revoked`；这是关闭授权的安全回退，**不是无损功能回退**。
  回退后不得重批绕过；待兼容版本恢复再查询原账本。此风险正式切换前另评估。
- 原用户规则保护用例及49,152字节原文边界保持，全局模板没有增大安装器预算或截断原文。

## 接续与未验项

1. 第04步：本地 IM 机器人统一通知／身份确认／方案确认／权威回执；对话稳定，不绑定 DSH session。
2. 使用两个独立测试机器人补做真实平台身份来源、原生 Desktop 和原生 IM 兼容验收。
   本步骤尚不能宣称真实飞书闭环完成；当前不要求用户重复注册或批准生产任务。
3. 第05步：异常核对、建议、修改、继续／结束的受控动作；不要拿本轮决定接口代替未知状态恢复。
4. 第06—07步：成果、受控下载与对话查询，隔离集成及正式切换前确认。
