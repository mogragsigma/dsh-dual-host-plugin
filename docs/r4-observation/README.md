# R4 任务观察与低打扰反馈

## 一、范围与来源

本工作包对应 F29、F17；恢复仍归 R3/F30，完整外置自修复归暂缓的 F33。
复用固定 DeepSeek super-agent 原型的 health/stage/report 思路，以及本产品已有任务合同、
原生活动、成果报告、通知授权和回执。没有增加常驻监督 Agent、Session 或第二套执行器。

本文件描述未发布的 v2.0 开发能力，不是正式 Host 已启用事实。
四类对话入口仍经原有任务接口查询整体进展、成果和追加指示；不要求用户管理 Session 或子代理。

## 二、实现边界

- 默认关闭。云端权威端启用 observation，执行端通过已鉴权 execution_validate 附带有界原生活动快照。
  没有新的消息消费者，也不改变任务与 IM 权限解耦。
- 程序判断区分正常等待、处理中、受阻、待核对、疑似未接续和未知。
  未来周期、资源冲突、3＋1 名额排队、人工暂停停止以及仍在运行的工具／后台工作不会误报为停滞。
- 持续疑点至少两次、有间隔观察才标记；原生活动计数、时间戳和日志存在不证明实质进展。
  不自动核验成果内容，不全量扫描文件、日志、历史会话或重新运行测试。
- 每轮最多 50 个任务，使用活动状态索引、当前问题索引和去重的变化任务 ID。
  已结束历史任务不因定时观察而全表重读。快完成任务通过变化记录补齐成果通知。
  观察表每任务一条，保存当前问题阶段、短证据、诊断和去重状态；不持续追加采样历史。
- 观察只读业务状态，只写自有观察／去重／通知记录。不暂停、重试、接管、释放占位、
  增加权限／预算、恢复会话或自动修复。观察故障不使有效执行失败。
- 同 Host 故障域不能保证自身宕机通知；联系不上执行端只表示未知，不等于已停。
  原运行保护仍然生效，与只读观察不冲突。

## 三、显式配置与成本

```json
{
  "continuity": {"enabled": true},
  "managedExecution": {"enabled": true},
  "observation": {
    "enabled": true,
    "intervalMs": 15000,
    "windowMs": 60000
  }
}
```

windowMs 只用于过滤交接瞬态，不是所有长任务的通用完成期限。
日常检查、健康状态及合理等待不调用模型。默认不启用辅助语义诊断。

如用户明确授权该端诊断模型及费用边界，可另配 diagnostics.enabled、policy、maxRequests、
绝对截止时间 endAt、timeoutMs。使用现有 DSH prepareCall/stream，不创建 Agent、Session 或工具调用。
输出最多 800 Token，每问题阶段最多一次；全局串行，累计请求记账，重启不清零。
独立诊断额度不替代／增加业务任务额度；未配置额度、路由或截止时间不得隐式使用主模型。
失败和未知请求不退款、不自动重试；原生底层若重试，每次实际 stream 均先占额度。
诊断只是一份假设，不覆盖原报告、已知事实或授权；任务变化／暂停后迟到的诊断不得作为当前结论。

## 四、通知与用户界面

- 复用既有通知目标授权、路由固定、队列、发送前核验及平台回执；无授权不发，也不在后来授权时补发旧事件。
- 仅明确需要处理的问题、持续联系未知和新成果进入必要通知；疑似未接续先显示，不自动反复催促。
  用户主动查询直接读取当前证据，解释复用当前对话，不另建监督会话。
- 同一问题阶段稳定去重；健康、正常等待、恢复默认静默。暂停后恢复同一问题不重新提醒。
- 仅已知同端、同 Provider、同错误代码、同授权目标合并，最多十项；不是把模糊相似问题当成同根因。
  合并文本明确是历史核对快照。只要其中仍有当前问题可发送；全部恢复或暂停则抑制。
  任一成员权限撤销，整批不再发送，避免泄露；不会为已知／未知在途消息自动补发另一批。
- 平台接受不等于已读。未知发送结果沿用 needs_review，不盲重试；发送后的恢复不能撤回消息。
- status 与任务详情使用 task_observation，避免覆盖双端传输原有 observation 元数据。
- 任务详情新增简短“等待与受阻”信息区；依据与辅助判断默认折叠，保留原整体任务操作与指引。
  不增加 Session／子代理管理按钮，不把诊断文字变成执行命令。

## 五、验收与限制

具名集合：scripts/run-r4-regression.py；另复验 R3、R2 和市场具名集合。
实际 Host 使用 DSH 0.2.2-rc.1 和合成 Provider，在本地及 ECS 隔离环境验证；
不代表真实外部模型质量、跨地域联调、真实 IM 送达或生产启用。

当前共同原因合并仅覆盖可证明的 Provider 标准故障；其他错误逐任务去重，不做模型猜测归因。
缺少进展证据不等于业务失败；保持原生活动的长计算仍可能需要用户主动询问。
没有引入外置 Watchdog、自动修复或新的删除策略；不自动删除会话。
