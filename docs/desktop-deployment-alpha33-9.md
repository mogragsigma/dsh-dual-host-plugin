# 原生 Desktop 与本地 IM 审批正式切换验收

## 结论与范围

已按用户授权完成正式 Mac Desktop 与 ECS 的切换，当前两端均为 **v0.33.0-alpha.9**。
不是仅部署到隔离 Host。官方 DSH 仍为 `0.2.1-rc.3`，官方 IM 仍为 `5.6.0`。
本轮未修改 DSH 或第三方源码，未覆盖用户规则，未新增业务任务或执行授权，未 commit、push 或发布。

本轮先完成 alpha.8 的原生审批兼容与存量路由迁移，随后正式下载回归发现相同的 Origin 缺失问题，
因此追加 alpha.9 小修复、重新双端隔离回归，再正式切换。alpha.8 冻结清单保留，不修改历史证据。

## 正式可用的用户路径

1. 打开「大肥鱼bot」→ 按名称选择任务 →「成果物」查看介绍、下载已登记报告或打开 Gitee 固定版本页面。
2. 「待你处理」区分方案决定、异常核对和维护处理，不把黄色状态都解释成同一种审批。
3. 工作台为主要入口。需要确认身份时，复用已绑定的本地 IM 私聊；不用新账号、通行密钥或特定操作系统。
   窗口身份核验只允许短时使用已有身份，不批准任务。每个决定仍需明确针对当前任务、修订和范围确认。
4. 支持批准、拒绝、暂缓和修改意见；有条件同意记为修改，不能执行旧方案。
5. 异常核对可展示原因、形成补充报告建议、查看结束范围或稍后处理。查看建议不重试旧批次；
   新建议仍需后续明确确认，不重置旧预算或扩展开发、提交、推送权限。
6. 本地 IM 作为辅助审批／权威回执入口，要求已绑定私聊和可核验的引用消息，不要求同一个 DSH session。
   历史任务的通知目标原样保留，不强制把旧群通知迁到审批私聊。

## 原生容器兼容修复

官方 Desktop 将 renderer 请求转交 Node Host 时会移除 `Origin`，且由官方 Host 注入 owner 会话。
原方案的 Web 同源检查使真实 Desktop 安全拒绝审批及下载。本轮未修改官方代理，也未关闭鉴权。

`native-owner-origin.js` 将例外限定为服务端检测到官方 Electron Node Host 的明确入口，
并且请求 Host 与该 Host 的精确回环地址、端口一致。原生 owner 鉴权仍在自有路由之前完成。
外站 Origin 和 `Sec-Fetch-Site: cross-site` 不放行，普通 Web 无 Origin 不放行。
该检查复用于工作台审批和成果下载；文件归属、修订、存在性、权限、大小及 SHA-256 检查未放宽。

本地 IM 出站通过官方 `credentials.resolve` 读取明确引用，不复制密钥到云端。
每次操作重新解析；轮换和撤销使缓存平台令牌失效；读取失败不退回扫描磁盘或未授权环境凭据。
不新建第二个官方 IM 消费者。

## 存量保留与迁移

- 原 38 个任务、21 个 job、32 个 run、13 份历史方案及 10 条历史决定完整保留；没有旧任务重试。
- alpha.8 审批路由迁移新增本地私聊绑定、禁用旧云端绑定，并更新指导版本；不改旧决定。
- 切换前再次确认没有有效旧审批、没有待发送旧方案；不凭早期只读副本代替最后核对。
- alpha.9 切换前后所有原业务表摘要相同。后续界面回归仅新增预期的身份／中继操作记录和异常观测，
  不改旧任务、job、run、方案、决定或成果。异常观察快照允许刷新，不把它当任务重试。
- 两端原凭据、官方 IM 配置和依赖清单摘要不变。全局规则的用户非托管部分逐字保留。
- 通过公开自有维护流程保留 20 个托管文件的归属；alpha.8 升级 6 个规则／Skill 文件，alpha.9 内容不变，仅推进安装版本账本。
- 原配置中的已有受限开发／交付能力未被扩大或重置；不能据本次零执行回归宣称所有历史执行器均未配置。

## 备份与回滚

两次切换分别保存离线备份、配置计划、候选 258／259 文件摘要、托管维护回执及核验结果，均在私有目录。
备份包含原 profile、会话、凭据、用户规则、Skills、自有状态；不得同步到源码仓库。

1. **alpha.9 回退 alpha.8：**只涉及下载 Origin 兼容；回退会恢复原生下载安全拒绝的问题，不应作为正常可用版本。
   先停机和保存当前状态，再回退自有代码路径及规则版本；业务状态不覆盖，核验同一审批路由兼容。
2. **回退 alpha32 原审批路径：**已演练离线副本还原；正式接流量后，不能盲目覆盖整库，也不能强制重新激活 disabled 绑定。
   必须保留所有新决定和身份操作，按迁移方案逐项核对；必要时仅恢复只读查询且关闭审批／执行。
3. 不重放旧消息、不清库、不重置预算，不把重新启动等同于新执行授权。

具体风险、旧绑定保护和接流量前／后区别见 [迁移方案](desktop-migration-alpha33-8.md)。
本轮已接收新的身份拒绝及观察记录，**当前不能直接拿最初整库备份覆盖线上状态**。

## 后续边界

- 新 DSH 版本必须重验官方 owner 会话、Desktop 转发头、实际 Host 标识和公共 credentials 服务。
- 本地机器人离线时辅助审批等待，不自动改投云端机器人或其他聊天。
- 原生模型可能对身份提示另作普通回复；不能代替插件身份状态或审批账本，也不能据普通文字要求重复批准。
- 没有新建业务任务进行开发／提交／推送验收，本轮不新增此类授权。
- 未执行市场发布或源码同步；现存部署与源码工作区状态应分开记录。
