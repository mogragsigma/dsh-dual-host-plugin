# 第04步：本地 IM 统一通知、确认与账本回执

候选 `0.33.0-alpha.5`，仅隔离验收，正式仍为历史 `0.32.0-alpha.11`。
主入口是本地工作台的具体任务；辅助入口是配置的本地机器人与已绑定私聊。
**同一机器人和对话，不要求同一个 DSH session；配对令牌不是批准人身份。**

## 用户动作

1. 在工作台选择任务、输入完整意见，核对系统解释与原方案。
2. 当前窗口尚无可信身份时，通过已绑定本地机器人核对专用身份提示，并回复确认。
   不注册账号或通行密钥；身份确认不是任务批准。
3. 回工作台保存本次决定。短时已核验窗口可逐案处理其他任务，不重复跳转。
4. 也可在同一私聊直接回复具体方案，表达批准、拒绝、暂缓或修改意见。
5. 工作台立即查云端账本；本地机器人发送独立的【DSH 审批账本回执】。
   用户先在工作台处理、方案尚未发往 IM 时，新决定也能按已核验绑定发回执，
   并指引回工作台处理，而不是让用户寻找不存在的原方案消息。
6. 业务结果通知使用同一目标，但仍须现有通知授权。旧任务不自动换收件人。

| Before | After | Why |
| --- | --- | --- |
| 身份提示写死云端审批私聊 | 按实际绑定显示本地或旧云端路线 | 说明与真实发送端一致 |
| 本地离线只出现通用失败 | 明确未发出，保留意见，等待本地恢复 | 不误导重复确认或换机器人 |
| 工作台先处理、IM 尚未送方案时无回执 | 新本地工作台决定按其可信绑定生成回执 | 工作台主入口不依赖 IM 先收到方案 |
| 无原方案时回执仍要求回复原文 | 指引回同任务工作台 | 不制造找不到入口的死路 |

本轮不改变浅蓝白布局、角色图、分页或手动刷新方式，也不新增介绍框体。
条件同意仍为修改重审；拒绝方案不等于结束任务；暂缓审批不等于暂停在途执行。

## 接线与配置

```text
本地工作台 ──原生认证接口＋自有配对 RPC──> 云端意见解释／审批账本
                                                │
                                  有界平台请求队列 approval_local
                                                │
本地凭据＋固定私聊适配器 <──配对 pull / validate / ack──┘
        │ 官方 HTTPS（无第二个 IM 长连接）
        └──本地 IM 机器人：身份提示／方案／回复读取／账本回执

原任务通知队列 ──原通知协议──> 同一本地机器人、同一私聊
```

- `bundle/approval-local-relay.js`：云端请求账本、本地执行账本、固定平台请求与新目标接线。
- `bundle/index.js`：仅显式配置 `localApproval` 才启用；`approval_local:1` 独立协商。
- `approval-chat.js`／`workbench-im-identity.js`：实际入口标识及原平台证据核验。
- `workbench-decisions.js`／`approval-ledger.js`：新本地工作台决定同时登记回执意图；
  不修改批准语义或运行门禁，不回填没有原投递意图的历史工作台决定。
- `approval-receipts.js`：原账本驱动发送，离线未发送不消耗平台重试预算。
- `task-focus-view.js`：真实路线说明与本地离线反馈；没有模型代确认接口。
- 全局规则、原生上下文与 `task-approval`、`task-notify`、`task-direct-link`、`task-sidebar`
  描述相同边界；本轮只改托管模板，不安装或覆盖用户规则。

双端 `localApproval` 提供相同的 `provider/appId/botOpenId/chatId/approverOpenId`。
本地另提供现有凭据引用 `appSecretEnv`；云端不需要该密钥，不转存密钥。
配置可选 `notificationAlias/notificationLabel`；默认命名目标为本地审批与结果。
不是把固定昵称写入产品；不是只有 App ID 就能向任意人发消息。

旧 `chatApproval` 与新 `localApproval` 不能同时启用；现有同名通知目标冲突时停止，
不覆盖、不自动迁移历史绑定。现有导览的用户选择、业务通知订阅不被静态配置重写。
本轮尚未把这个新增绑定迁移做成六页导览中的一键生产切换。

飞书适配器需要原有读取／发送消息权限及私聊类型核验权限。本轮测试机器人补开
`im:chat:read`（只读），官方接口核验机器人和私聊通过；没有修改日常应用权限。
其他 IM 平台未来需要同等级的官方身份／引用回读证据，不能因共用通知接口就宣称已支持可信审批。

## 安全和恢复

- 中继仅允许 verify/get/list/send/reply 五类固定请求，无任意 URL、聊天目标或决定参数。
  当前版本仅接受已配对 local 节点拉取／回报；cloud 节点不能伪装 local 回报。
- 请求和 ACK 校验绑定摘要、操作引用、参数、大小与截止时间。读取其他私聊失败。
  超长证据拒绝，不截断成一个可能被误判的批准。
- 每次决定仍独立回读官方原消息、本人身份、引用、原文和时间；中继不生成批准人。
  本地管理员可改插件／数据库的边界仍存在，不宣称操作系统身份隔离。
- 本地离线不回退云端机器人。已知未投递方案保留；未发送回执保留队列。
- 云端重启：在途平台请求保留待核对，不重新发送。过期未领取请求取消，已领取保留未知。
- 本地重启：已持久成功结果可重复 ACK，不重复发送；中断执行标记未知，迟到旧进程不能覆盖该标记。
- 发送前再核对当前云端请求。超时或丢 ACK 不以换编号／重新请求来绕过。
- 新本地工作台回执意图与决定同事务写入。历史启动回填不携带新路由授权，
  不因升级把过去没有回执的工作台决定自动发给本地机器人。
- 审批不自动启动 worker、解除写入、commit、push、发布或部署。
- 降级到无 `approval_local:1` 的对端会阻断该通道，不降级到旧机器人；恢复需保留自有账本。

测试记录与截图仅保存在忽略的私有验收目录，不进入源码分发。

| 范围 | 本轮证据 | 不代表 |

| 官方 Host | 本机两套全新 `0.2.1-rc.3` Web Host、独立 HOME／端口／状态；standard/ptc/cordis/minimal 各85/85/88/3工具可加载 | 原生 Desktop 容器、真实 ECS 或生产部署 |
| 真飞书身份 | 独立测试机器人，官方平台原消息；按用户测试授权通过浏览器代输入确认 | 用户本人手打或真实业务批准 |
| 真工作台决定 | 修改、批准、暂缓均写入云端隔离账本；身份在同一窗口可逐案复用 | 任务已执行 |
| 真 IM 辅助决定 | 回复测试方案自然语言拒绝，云端记账并由同机器人发送权威回执 | 其他渠道均兼容 |
| 原结果通知 | 另一组独立 Gateway 的合成完成事件，走原通知队列／配对／平台，消息在同一私聊可见 | 真实模型或 worker 完成了业务成果 |
| 无原方案回执 | 修复后工作台批准、暂缓各产生同私聊平台核验回执 | 补发修复前的历史修改意见 |
| 双端重启 | 最终255文件测试副本与冻结清单一致；任务、审批、介入、窗口身份、回执逐行保留，原用户规则未改 | 正式无损升级 |
| 离线恢复 | 停止隔离本地 Host 后新方案保持 queued、无消息；恢复后官方回读恰好1条 | 正式离线演练 |
| 安全失败 | 错节点／绑定／私聊／大对象、断线、ACK丢失、超时、重启、重复保存和历史不迁移 | 管理员隔离 |

本轮未改第三方源码、旧消费者、日常配置或用户规则；未调用模型、启动业务 worker、操作 Gitee、
提交、推送、正式部署或发布。没有向云端复制测试机器人密钥。

## 后续

第05步处理“异常核对→提出建议→输入意见→继续或结束”，各动作需要明确且独立的授权范围。
之后补成果入口和完整隔离总回归。原生 Desktop、真实 ECS、原生 IM 消费者共载下的完整聊天流程和正式路由迁移须单列验收，
不能把本机双角色 Host 当成生产双端通过。

收尾已正常停止本轮新建的两套测试 Host，并关闭本轮验收浏览器空间；证据和状态保留，日常环境未动。
