# alpha32 正式双端收尾验收

## 结论

本轮四个工作包完成，正式 Mac Desktop 和原 ECS 均运行 `0.32.0-alpha.11`。
官方 DSH 为 `0.2.1-rc.3`、官方 IM 为 `5.6.0`，未修改两者源码；本轮没有 commit、push 或发布。
这是**已有 DSH 的保留数据重装与既有配置复用验收**，不是空白 OS 或市场首次下载全链路的替代证据。

## 工作包与证据

| 工作包 | 实际结果 | 证据边界 |
| --- | --- | --- |
| 1. 基线、备份与正式切换 | 双端逐项备份、只更换自有接线，最终 alpha.11 正常重启在线 | 配置、依赖、用户规则和旧业务记录分别核验 |
| 2. IM 选择与定时通知 | 本地／云端选择均经真实飞书收发与延迟单批任务验证；Mac 离线入队、恢复原投递、重启不重复 | 主要真实通知验收在 alpha.6/7；alpha.11 保留原策略，新本地通知再次实测 |
| 3. 自有制品卸载重装 | 精确移除并恢复历史手工插件入口；卸载期间两端原生 IM 仍能回复；公开安装器管理每端 20 文件 | 不冒称历史手工插件本体具有官方包管理归属；规则维护只用真实账本 |
| 3. 六页复用 | 正式 Desktop 实际点击完成 1/6—6/6，并保存复用回执 | 复用原生产云端，不另建替代 Host，不复制密钥，不伪造接管 |
| 4. 任务及成果 | 新只读定时任务完成，报告与执行会话可打开；Gitee 旧成果通过固定版本 API 核验 | Gitee 没有浏览器依赖，没有新写入、提交或推送 |

最终空闲重启后，本地 89 个、云端 44 个原生会话均保留，运行中为 0。
两端原生 IM 在线；重启前后的全部业务表相同，仅通知扫描游标等运行元数据允许变化。
所有旧业务行保留，审批／开发／交付表没有新增；用户 AGENTS 原文分别为 1352／85 字节，逐字节保留。
原凭据记录未修改，本地仅新增自有六页确认 grant；原导览草稿保留，云端原凭据无变更。

## alpha.11 修复与回归

正式 alpha.10 第 3 页暴露通知视图字段插入顺序差异：语义相同的 `{host,label}` 和 `{label,host}`
被原始 JSON 比较误认为不同。alpha.11 只规范只读比较投影，不改持久指纹、授权、收件人或同步操作。
新增测试组合真实本地公开视图和云端 SQLite 视图，验证两种默认端，以及修订、操作、端和名称漂移仍拒绝。

- 新测试修复前失败证据保留；修复后 Mac／ECS 各 51 项定向通过。
- Mac／ECS 各 208 项安全导览回归通过，测试集有重叠，不能合计或称全部历史测试。
- ECS 首次测试包遗漏 UI 夹具导致 8 项失败，补齐未改动夹具后重跑通过，失败日志保留。
- 全新官方 rc.3 回环双 Host 验证原生公开 RPC、托管安装、合成目录、确认及重启读取。
  该项零模型、跳过可选 IM/Gitee，明确不替代正式真实验收。
- 冻结候选为 `candidate-bundle-alpha32-11.json`，249 文件；旧版本清单不改写。

## 正式六页与真实任务

1. 核对原双端连接、实际版本、路径及每端 20 个托管文件。
2. 输入 `ds flash`，唯一解析至云端官方 `deepseek-flash / high`，没有硬编码 provider 输入要求。
3. 复用已有本地机器人私聊通知，核对双端同步一致；保留原 revision=2，没有重新授权或迁移收件人。
4. 通过云端 API 只读核验既有 B 线私有任务仓库、main 和固定基线；未克隆或创建业务绑定。
5. 核对全局规则与 Skill 归属，保留用户原文；没有新增权限。
6. 预览并确认，只新增本插件配置复用回执；最终正常重启后该回执逐字段保持。

随后通过真实本地飞书交办独立的新任务「S67 六页复用后成果验收」：
60 秒延迟，`max_runs=1`，最多 6 次模型请求，官方 `deepseek-flash / high`。
实际 1 批、1 次尝试、5 次模型请求完成，独立 worker 保存 312 字节报告，结果为 3×7=21。
原生会话记录实际模型、high、五次响应、`task-worker`／`task-artifacts` 加载及成果和报告工具。
入口先返回，不等待定时 worker；未访问外部资料或调用 Shell，未写仓库。

结果自动继承导览默认本地通知，SDK 接受且真实飞书可见；最终双端重启后 attempts=1，未重发。
“接口接受”“聊天可见”和“用户已读”分别报告，本轮不声称用户已读。
Desktop 成果卡片核验后打开正确云端执行会话；Gitee 既有 README 的版本和散列由 CLI/API 再次核验。

## 保留的限制与非阻断项

- 之前那条输出额度耗尽任务仍是原 `needs_review`、attempts=1，未重试、换名复跑或覆写失败。
  新验收是六页复用后的独立任务，成功不证明 2048 token 的 high 输出额度问题已普遍解决。
  当前诊断会对未来截断报告 `WORKER_MODEL_OUTPUT_LIMIT`，不会自动加预算。
- 原生产 Host 和历史手工插件入口不被伪造为导览新建受管实例。六页“复用”与“新环境初始化”各有边界。
- 第 6 页无障碍进度值仍为 5、已确认页底部仍含未保存填写提示；回执真实保存且可恢复。
  留作非阻断文案/显示优化，本轮不再次扩展 UI 或核心动作。
- 默认通知当前为本地机器人本人私聊，这是本轮已保存的选择，不是所有用户的固定默认值；另一端原生 IM 不被停用。
- 现有受管开发／提交／推送总配置原样保留；本轮没有新增任何业务写入批准，不能写成全局开关都关闭。
- 备份、原始会话、配置和凭据只保存在受限维护目录，不进入源码仓库或报告正文。

## 后续维护

本轮范围结项，不自动开始市场发布、全新用户扩展验收或输出预算改造。
