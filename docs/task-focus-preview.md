# 成果与待办前端预览记录

## 界面与交互

| Before | After | Why |
| --- | --- | --- |
| 默认详情展开模型、队列、执行、审批、仓库等多个框体 | 默认集中「成果物」与「待你处理」，其余通过「任务信息与诊断」打开 | 优先呈现用户能查看、能操作的内容 |
| 多类黄色状态混在一起 | 区分有效方案、补充问题、执行核对、通知核对和能力问题 | 待核对不是待审批，不能用批准代替排障 |
| 工作台只能查看审批 | 预览有意见输入框和同意原方案／暂缓／拒绝按钮 | 先验证操作位置、反馈和条件保留，再接真实身份 |
| 模拟决定后可能仍看到旧状态 | 决定结果单独保留，显式动作后刷新一次列表与详情 | 避免重复批准；没有新增定时轮询 |
| 无成果仍显示不可用入口 | 已登记成果才显示相应入口，来源与版本折叠 | 降低噪声，保留核验依据 |

保持浅蓝白、已有角色图、左侧时间线、关键词包含搜索和手动刷新。
任务标题旁显示待处理提示；窄屏按钮自动换行。诊断按需挂载，关闭时还原键盘焦点。

模拟方案支持无条件批准、拒绝、暂缓、有条件同意和需澄清；条件文本不会因点击“同意原方案”被丢弃。
过期或旧修订方案不能提交。任务执行失败、历史未闭合记录、通知结果未知没有批准按钮。
模拟暂缓表示暂缓审批，不能显示成 worker 批次已暂停。

## 实现与三制品边界

| 文件 | 本轮职责 |
| --- | --- |
| `ui-source/task-focus.mjs` | 只读状态投影与方案选择，不授予执行权 |
| `ui-source/task-focus-view.js` | 待办、输入、按钮、回执与诊断组件；无可信适配器时关闭提交 |
| `ui-source/workbench-client.js`、`overrides.css` | 整合紧凑布局、成果入口与动作后一次刷新 |
| `scripts/build-ui.py` | 生成 `bundle/workbench-client.js`；不手改生成产物 |
| `ui-source/preview/task-focus-preview.jsx` | 合成任务、内存决定及模拟下载；不加载 Host 凭据或配置 |
| `scripts/build-task-focus-preview.mjs` | 用隔离构建依赖打包共享 UI，输出到忽略目录 |
| `bundle/global-rules/AGENTS.md` | 自有模板补充预览非授权、核对非审批、身份不绑定 Mac |
| `bundle/skills/task-sidebar/SKILL.md` | 说明新视图和未接通的真实动作，不安装或覆盖用户文件 |

真实 Host 的调用方没有传入审批、讨论或下载适配器，因此这些新动作不会在实际运行时生效。
预览复用现有语义解释模块的确定性分支，不调用模型；无法识别的意见保持待澄清。
示意 Gitee 链接被预览拦截，模拟下载由浏览器生成合成文本，不读取任何 Host 文件。

## 回归与限制

最终定向集合为 154 项：153 通过、0 失败、1 项历史比较跳过。
包含新界面状态、草稿、重复点击、迟到回执，以及原有任务看板、成果、语义审批、交付、仓库和 UI 契约。
不是全部历史测试，也不是正式双端、真实 IM 或真实人类身份核验验收。

浏览器独立复核桌面 1492 像素与窄屏 390 像素：

- 同意、拒绝、有条件同意后的列表、详情和模拟回执一致，旧表单无残留。
- 暂缓保留相同方案；失败、待补充、过期案例没有错误批准入口。
- 搜索、手动刷新、诊断关闭、Escape、焦点返回与可见 Tab 焦点通过。
- 两种宽度没有按钮重叠或横向溢出；窄屏不是手机真机兼容性证明。
- 最后一项暂缓文案修正经自动化验证，不冒称再次完成全量浏览器复测。

本轮修复两个前端问题：显式决定后的快照不同步，以及重复 React 同级 key 导致的旧表单残留。
未知处理结果保留草稿，不自动重试；当前前端错误提示不代替未来服务端的持久幂等核对。

扩大回归时发现历史 UI 测试仍比较 PNG 元数据清理前的文件哈希。
资产本轮没有变化；测试改为比较已提交的 `source-bundle-alpha32-11.json` 源码导出哈希。
原验收哈希、正式冻结清单和源码导出基线均未改写，未以更新基线隐藏界面改动。
历史 alpha69 的全文件 UI-only 比较因版本不同沿用原跳过规则。

生成产物语法检查、模块索引一致性和 diff 空白检查通过。
截图和完整测试日志在本地忽略的预览目录，不上传私有浏览器数据。

## 后续接线顺序

1. **工作台可信决定**：补充不依赖 Mac 的操作人身份核验、当前方案／版本重新核验、幂等决定及权威回执。
   复用已有账本门禁，不能把 Host 登录、端点配对或按钮点击当作批准人证据。
   自然语言有条件同意必须进入修订；未知结果查询原操作，不自动重放。
2. **所选机器人统一**：通知与审批使用同一选定的本地或云端机器人，并分别核验目标对话与批准人。
   通知目标可用不等于批准人绑定已完成；不修改第三方插件或悄悄回退其他机器人。
3. **主对话辅助入口**：按任务关联发起会话定位／讨论，不向任意已有主会话插入消息。
   当前已有按名称查询任务／成果的工具；新增的是明确上下文和操作导航，不能伪造已执行。
4. **受控下载**：自有只读接口按成果标识核验任务／批次归属、存在性、权限、大小与有效性。
   不接受任意文件路径，不暴露云端登录材料，不把 Gitee 页面入口冒充文件下载。

这些真实动作尚未完成，不能以本预览回归通过作为正式启用依据。
后续继续隔离验证；正式部署与市场发布仍不在当前执行范围内。
