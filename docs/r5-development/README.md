## 二、任务合同与流程

`task_execution_prepare` 可带 `development`，并通过已有任务级决定批准；四类入口相同，
不增加个人凭证，不依赖 IM 审批，不把连接仓库或机器人权限当作研发授权。

```json
{
  "delivery": "push",
  "branch": "task/example",
  "remote": "https://github.com/example/project.git",
  "checks": [{"name": "相关单测", "command": "npm test"}],
  "artifacts": ["reports/result.md"]
}
```

1. 交办时结合目标、原始限制准备任务级合同。交付模式为 workspace、commit、push 或 pr。
   原生 CLI 写入只在明确约定模式内开放；不自动包含合并、发布、部署、改写历史和删除分支。
2. 执行者读取仓库规则及当前差异，用原生工具调查、修改、测试、修复、提交、推送与 PR。
   `managed_evidence` 保存当时差异及验证记录，不执行 Git 写入。
3. 命名检查由原生 bash（本地由固定 managed_command 名称）执行，捕获真实退出状态。
   未运行、失败、后台未收尾、未知、检查中改动，以及之后发生的相关改动，都不能冒充通过。
4. `managed_artifact` 留存约定相对路径的真实文件。草稿可立即取用，历史版本仍可下载；
   不需要结束任务或人工恢复会话。候选成果不是用户验收。
5. `managed_report ready` 核对当前检查、执行者自检和约定 Git 交付回读。退出前再次核验，
   后台工作仍按 R3 排空；工作者自检明确标注，不冒充独立审计或 UI 视觉验收。
6. 可选 `notification:{target_key,binding_revision}` 引用已保存的具体通知目标。
   原生执行排空后自动把当前版本 candidate 加入既有发送队列；发送前重验文件摘要、任务授权及目标。
   仍走既有通知队列，不新增发件器；修改 IM 配置不能给任务新增权限。

同一任务/修订/路径/阶段/内容有稳定成果 ID；发送去重绑定任务、目标与成果，而不绑定新审批 ID。
续批不能把结果未知的同一份交付变成新发送；每次实际发送仍检查当前有效授权。
结果未知只查原记录，不能换事件 ID 自动再发。平台接受、下载请求、落盘、已读与用户验收分开。

## 三、Git 与本地边界

- 执行端 Git 是基础；无远端也可以完成文件或本地提交交付。普通文件任务可省略 branch，
  不要求初始化 Git 或绑定 Gitee。已有仓库不迁移。
- 本次 PR 薄适配是 GitHub `gh pr view` 只读回读，核对仓库、head、base、提交、OPEN、非 draft。
  创建与维护仍由原生 CLI 完成。不宣称已有 Gitee/GitLab PR API 适配。
- 新合同使用 managed_development 能力协商；旧执行端只能领取旧合同，不能领取新研发合同。
  云端拒绝缺少当前研发证据的 ready 回执，不能回落到旧执行器冒称完成。
- 推送核对实际远端分支 OID，不将“命令已执行”当作远端已接受。
  超时/未知不自动再 push/create；无权限/平台缺失时如实等待条件。
- 原生任务按 Git common directory/仓库资源串行；旧开发与交付账本的 active/needs_review
  资源同样阻止新任务抢占，新旧实现不并行写同一仓库。
- 云端沿用执行账号广泛文件权限。命令策略不是任意 Shell 沙箱；任务提示词、显式风险检查、
  专用账号及平台权限共同构成边界，不宣称可以阻止任意间接脚本绕过。
- 本地不新增任意 bash/Git 写权限。受管本地仍只处理获准副本及既有 macOS 固定命令；
  R5 本地合同限 workspace 且省略 branch，按普通文件记录差异。普通本地 DSH 原生能力不变。

## 四、成果与资源保护

- 原生快照支持普通文件，不限于旧报告的六种格式。48 KiB 分块贯穿双端传输、下载和既有媒体发送；
  不使用公开临时 URL，不把凭据带到浏览器，不在聊天中转发文件二进制。
- 当前实现保护值：单快照 64 MiB、每任务原生快照累计 256 MiB、既有成果目录上限 100 项，
  最多 32 个未完成上传。超过时明确拒绝；不是此前固定 2 MiB 产品文件上限，也不是无限存储承诺。
  旧 peer_file 产品能力及其历史上限未在本轮重写。
- 差异扫描最多 5,000 项/64 MiB；超限不假装完整检查。摘要最多 16 项与 32 KiB Git 摘录；
  二进制和截断如实标记，仍可使用原生工具继续核对。
- Git 摘录相对开始时提交，可能包含用户已有改动；任务净变化另对比开始时文件摘要。
  指定成果即使被 Git ignore，也参与检查的新鲜度判定。
- 不读 symlink/hardlink 成果、不执行成果、保留历史字节；无自动会话/成果删除。
- UI 只提供成果取用与折叠的差异/验证记录，不增加会话管理或每条 Git 命令的用户操作节点。
