# alpha69 验收与限制

## 一、冻结基线

- 版本：`0.31.0-alpha.69`；本轮官方 DSH `0.2.1-rc.3`，IM `5.6.0`。
- `bundle/` 共 245 个文件，与冻结候选逐文件 SHA-256 一致。
- [冻结文件清单](candidate-bundle-alpha69.json) 保留原字节基线；源码索引不包含秘密、会话或运行态。
- 纯 DeepSeek 新用户链路的真实验收模型为 `deepseek-flash / high`，不是产品固定模型。

## 二、已有真实证据

| 范围 | 结论与证据边界 |
| --- | --- |
| 双端新隔离 Host | 六页导览、官方原包、三制品、模型与 IM 接线通过；不借用日常 Host |
| 真实 IM 任务一 | 同一 job 两批、检查点后 Host 重启恢复，8 次 worker 请求预留；报告核验通过 |
| 真实 IM 任务二 | 先授权通知目标，再执行一批，5 次 worker 请求预留；未来完成通知实际群内可见 |
| 主会话 | 检查点等待期间仍可交互；另外有活跃 worker 并行原生响应的隔离探针 |
| 成果入口 | 本地工作台成果卡片打开原云端第二批执行会话，无新增 job／run |
| 通知边界 | 第一任务完成后晚绑定目标不追溯发送；群内可见不等于用户本人已读 |
| 三端文件 | 沿用前序收尾中 IM／本地／云端六方向真实模型与文件证据，未在 alpha69 全部重跑 |
| Gitee | 前序同一收尾周期完成独立凭据交接和目标端私有 B 仓库只读；无 commit／push |
| 用户保护 | 用户全局规则保留、原 DSH／第三方源码未改；未重放旧任务 |
| 日常环境 | 只获批恢复旧 v24 的精确兼容例外，非 alpha69 正式部署 |

两项真实 IM 任务共 3 批、13 次 worker 请求预留，**不包含入口模型请求**，也不等于全部 API 消费次数。
原始证据包含私有环境信息，保留在维护现场；仓库只导出此去敏摘要，不上传私人日志或截图。

## 三、定向回归

alpha69 冻结时 Mac 与 Linux 各 **206 项通过、0 失败**。
当前源码导出在旧 checkout 首次遇到缺少新增 peer 的安装环境问题，按锁文件重新执行 npm ci 后复验；
未修改产品源码绕过依赖。最终结果另见 [source-export-validation.json](source-export-validation.json)。
历史约 2000 项及早期开发／提交／推送回归没有在 alpha69 全部重跑。
当前明确集合由 `scripts/run-onboarding-regression.py` 维护；历史测试文件继续保留，不应通配执行。

源码导出清理了三处行尾空白，并把一个旧上游夹具测试改为显式环境变量路径，避免访问维护者机器目录；不改变 bundle 字节。
它仅针对历史 IM 5.0.3 契约，不在 206 项集合内，不证明 IM 5.6 所有接口兼容。
未配置 `DSH_TEST_IM_VENDOR` 和 `DSH_TEST_REACT_FILE` 时应跳过，不能自行定位日常安装。

## 四、尚未承诺的事项

1. 未正式部署候选、未发布市场版本；此次 Git 推送只同步 A 仓库源码及维护文档。
2. 新用户验收未开放实际开发、commit、push；历史能力代码存在，不表示新导览默认启用。
3. 未完成 Windows 真机全链路；路径解析覆盖不能替代原生 Host／SSH／UI 验收。
4. 未建立系统账号隔离；原生 Shell 与其他插件不受自有门禁的系统级约束。
5. 云端首次模型预览曾出现通用错误，之后真实请求成功；根因未定，不称其已修复。
6. 原生 IM 目录选择器前台等待有原生 `/workspace` 替代操作，不修改第三方源码。
7. 历史漂移现场保持不动，不以删除旧环境作为候选通过条件。
8. 市场发布元数据、完整许可／素材来源复核及发布前全矩阵另行安排。
