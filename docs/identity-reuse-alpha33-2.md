# 第01步：复用现有身份

候选版本 `0.33.0-alpha.2`。本轮仅在隔离环境验收，未正式部署或发布，未提交或推送源码。
正式环境没有重新核验，也没有访问其配置或凭据；不能把本报告当成正式运行状态。

## 结论与范围

第 01 步完成的是**旧身份路线撤除、可信证据边界和可用入口说明**，不是工作台真实审批完成。
本地工作台是主入口，本地 DSH 配置的 IM 机器人及绑定对话是辅助入口；后续不得回到重复注册路线。

- 不使用通行密钥、设备专属认证或新账户注册。
- DSH owner 登录只证明 Host 访问权限，不证明具体审批人的身份。
- 机器人 App ID 只标识应用；通知送达只证明投递结果，两者均不授予批准权。
- 可信 IM 回复仍须核验应用、机器人、绑定的人与对话、原方案及回复关系、版本和有效期。
- IM 对话窗口可以固定，内部 DSH session 可以变化；任务与待处理事项必须独立持久关联。
- 原有审批私聊保留原核验流程；**本地 IM 统一确认尚未接线**，不能因已能发送通知就冒称可用。
- 历史身份、挑战、证明、决定均保留；没有删除用户设备上的凭据，也没有重放旧确认或撤销历史决定。

后续工作台复用现有可信身份时，关联当前操作窗口与批准具体任务必须分开。
仅在需要补足证据时使用已绑定 IM；不因一次任务确认隐式创建长期授权。
本轮没有实现或默认授予此类会话授权。

## 用户看到的变化

| Before | After | Why |
| --- | --- | --- |
| 要求登记通行密钥，遇到容器差异可能无法继续 | 不再出现注册、设备验证和系统凭据调用 | 不增加用户身份管理负担 |
| 点击批准后才发现身份接线缺失 | 显示“查看当前处理方式”，说明现有入口和缺项 | 不把未实现能力伪装成可用按钮 |
| 旧快照连只读说明也无法查看 | 仍允许查询最新处理方式；服务端复核任务版本 | 不要求多点一次刷新才能看说明 |
| 输入意见容易误认为已经提交 | 标明“你的意见（尚未提交）”；查询不发送意见 | 避免虚假完成感 |
| 将已配置通知机器人说成可审批 | 区分已配置、不可用、待核对、尚未接线 | 不让用户反复到错误聊天窗口确认 |

意见仅在当前页面内存中保留，切换任务后可返回编辑；**不声称刷新或关闭页面后仍持久保存**。
预览仍为模拟数据，不能作为真实业务授权。

## 实现定位与契约

| 文件／模块 | 本轮作用 |
| --- | --- |
| `bundle/approval-workbench.js` | 只读核对当前 IM 绑定、方案与投递记录；不调用模型或外部平台 |
| `bundle/workbench-host.js`、`bundle/index.js` | 复用官方受保护工作台接口和自有配对协议；不增加模型审批工具 |
| `bundle/link-contract.js` | `approval_workbench:2`；与旧 v1 不兼容时拒绝，不回退旧注册路径 |
| `bundle/approval-http.js`、`bundle/approval-auth.js` | 旧入口兼容墓碑，明确停用，不创建任何新身份或决定 |
| `ui-source/approval-workbench-client.mjs` | 仅请求只读说明，不调用浏览器凭据 API，不自动轮询或重试 |
| `ui-source/task-focus-view.js` | 保留紧凑任务输入框与蓝白风格，撤掉无效操作入口 |
| `bundle/global-rules/AGENTS.md`、相关 Skill／自有规则模板 | 同步主辅入口、证据边界和尚未接线说明 |
| `tests/fixtures/legacy-approval-auth.mjs` | 仅构造历史账本证据；不在插件包内，不是现行认证实现 |

`approval_workbench_describe` 接受空参数，或完整的任务、方案、修订定位。
禁止调用者提交 principal、owner、approved、App ID 等来指定自己的身份。
返回 `schema:2`、`read_only:true`、`enabled:false`、`registration_required:false`，
并始终返回 `identity_verified:false`、`approval_granted:false`、`execution_granted:false`。
“configured”仅是配置证据，`verified_now:false` 明确没有本次平台活体核验。

旧 prepare／begin／finish／status 返回停用错误；不继续旧挑战。
旧 `/approval/` 页面、脚本及动作返回 HTTP 410，不发 Cookie、不读取请求来创建身份。
该错误归为人工核对而非可自动重试的网络错误。
历史决定仍可从原审批账本和任务状态查询，不删除历史状态来掩盖失败。

运行包已移除两项认证依赖；历史密码学夹具依赖独立留在 tests 下，运行此类测试前用
`npm ci --prefix tests --ignore-scripts` 安装测试依赖。它们不随插件分发，也不能用来证明真实用户验收。

## 隔离回归

- 定向单元／接口／UI／安装保护回归：415 项，414 通过、1 项历史跳过；不是所有历史测试的总回归。
- 覆盖旧注册退役、伪造 owner／App ID／布尔批准、混合版本、未知发送、失效绑定与历史证据保留。
- 原 IM 语义、回执、引用和有条件同意回归继续通过；使用合成平台夹具，不冒称本轮真实飞书发送。
- 两个全新官方 DSH `0.2.1-rc.3` Web Host 均位于本机隔离目录，分别运行本地与云端角色；**不是 ECS 实机**。
- 两端原生 standard、ptc、cordis、minimal 预设加载通过；无模型请求，无日常配置或凭据。
- 两端未登录的工作台请求均返回 401；登录后只返回接线说明，不因此授予批准权。
- 重启前后任务、修订、审批记录逐项一致，用户规则哨兵原样保留；没有重试旧任务。
- 安装保护覆盖保留 49,152 字节的用户原规则、BOM／CRLF、权限与 Skill 冲突；没有提高容量上限或截断原文。
  初次复验发现新增模板超预算，已将细节收敛到 Skill，全局模板回到 12,106 字节。
- 真实 Ego 浏览器完成进入任务、输入条件意见、查询处理方式及跨任务草稿保留；没有出现系统身份注册提示。
- 两个测试 Host 和本轮浏览器空间已关闭，保留私有验收记录；未改动原模拟预览。
- 首次使用共享回环地址出现 HTTP 431，改用该隔离 Host 的 localhost 地址后通过；未清理用户 Cookie。
- 原生 Desktop 容器、真实本地 IM 统一确认、跨操作系统真机授权属于后续验收，不纳入本步通过项。

第 02 步先解决“哪件事需要我做什么、做完会发生什么”，不让用户辨认内部 ID 或猜测黄色状态。
不在本轮扩展执行、开发写入、提交、推送或发布权限。
