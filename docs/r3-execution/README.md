# R3 受管执行（隔离开发，待用户验收）

## 一、当前状态与边界

正式版本仍是 0.33.4。当前未提交工作树包含 R1、R2 和 R3 开发改动；版本声明仍为
0.34.0-alpha.2，不以同版本重新打包发布。本轮不提交、合并、推送、发布或部署。

2026-11-07 按用户最新决定实现：**云端广泛文件权限、任务级授权、必要高风险保护**。
云端 cwd 是工作起点，不是每任务文件沙箱；不新建 Linux 执行平台。
本地保持 F10-B 边界。开发测试外层隔离保持不变，绝不将正式 Host 数据当作测试夹具。

`managedExecution` 默认关闭；只有显式配置才接入新执行合同。已经保存新合同的数据库
不能通过关闭开关回落到旧执行器。四入口、任务与 IM 权限解耦和普通 DSH 能力保持。

## 二、实现与来源

| 模块 | 责任 | 复用与新增 |
| --- | --- | --- |

## 三、当前可验证行为

1. 执行端默认模型可被显式模型覆盖，保存原生解析路由，不强制 high，不再限制 6 次请求／2048 Token。
   请求预算持久化，失败与未知请求不退款。默认 200 次、连续运行 1 小时、合同有效 7 天，均写入方案可调整；
   长周期必须明确更长有效期。任务的有效期或额度耗尽不自动加额。
2. 按 CR-02，云端普通名额最多 3 个；普通满时，既有任务的直接人工跟进最多再占 1 个。
   本地独立上限为 1，不与云端共享名额，也不把云端 +1 扩展到本地。
   排队不创建 Session。相同任务／相同规范工作目录互斥；后台作业仍占位。
   目录互斥不是对任意云端文件的完整冲突检测。
3. 云端使用执行账号权限，保留原生文件、Shell、页面读取、Skill、Jobs 和任务内子代理工具入口。
   显式提权、已知高风险命令、直接敏感数据路径有拒绝门；未授权例外要求报告等待。
4. 本地端沿既有鉴权 DirectLink 向云端领用任务，在本机任务副本内实际读写。
   通过 managed_command 执行合同批准的设备命令名称；不启用任意 Shell、派生进程、越界文件或网络，不回退无约束运行。本地子代理仍不启用。
5. 原生 Session 跨轮次复用；闲置 7 天且无活动才归档。后续自动恢复同一 Session，
   不删除、不创建替代 ID。活动归档拒绝；明确停止活动并归档转为任务暂停。
6. 跟进保留原文；执行中提示 Worker 按需读入，未读跟进在当前执行排空后接续。
   暂停／停止优先。周期恢复只排下一轮，不补跑全部错过轮次。
7. 同任务重新授权后可调整模型、累计请求上限、有效期及周期；必须先排空。
   保留原任务、原 Session、历史输入与已用请求，累计上限不得低于已用额度；不更换端角色或 cwd 偷换 Session。
8. 原生工具派发前落不确定标记；只有工具结果持久化且无在途工具／原生后台作业时才保存安全检查点。
   端点重启持有独占锁后自动核对，安全断点接续原 Session；旧候选无检查点、仍有活动或副作用不明时不盲目重跑。
   未开始且已回收的旧认领可以收敛回执，不干扰新认领。不把失联当空闲。
9. 连续运行时间到限转为等待，不自动重开窗口；非安全中断显示需要核对，不误报完成。
10. 回执只有原生执行、后台作业与持久化排空后才提交；失联的运行占位不因租约过期自动释放。
   完成回执幂等。任务查询与成果查询可读取 managed_execution 整体状态和报告，不需 Session 操作。

## 四、本轮补齐及明确限制

1. 搜索通过 managed_search 复用 source-search 中公开的 DeepSeekSearchProvider。合同写明范围、
   辅助模型（deepseek-official、明确 model、reasoningEffort=disabled）和累计搜索子额度；
   搜索同时扣减任务总请求额度。每次最多一次服务端检索、2048 输出 Token、5 条结果。
   这是搜索辅助请求限制，不是主任务的短批次限制。先预留再派发；失败或回执未知不退款、不自动重发。
   重新批准可调整累计上限，不能低于已用数；历史请求保留模型路由。网页正文需另按已有页面读取能力处理。
   未批准的原生 web_search 旁路仍拒绝，普通 DSH 搜索不改动。凭据只引用执行 Host 的 credentialRef。
2. 本地 managed_command 使用 macOS Seatbelt，运行前检查任务副本、硬链接和临时目录，清空继承环境；
   只允许副本读写及系统运行库／设备预配置可执行文件的只读加载。网络、Mach 服务查找、fork/posix_spawn
   均拒绝；不创建 Linux 平台，不升级权限。超时或取消杀死唯一执行进程，等待 close 后才完成回执。
   命令由设备配置给出固定 executable、args、timeout_ms，任务仅批准名称，Worker 不能追加参数。首次使用后固定该任务的命令定义指纹；设备侧同名改配置会拒绝执行，应使用新名称并重新获批。
3. 当前是**受限单进程构建／测试**，不等于任意 npm、Shell、多进程工具链或后台服务可用。
   Node 原生测试可使用 --experimental-test-isolation=none。需要派生子进程、联网安装依赖或读取副本外
   用户文件的构建应如实报告不支持，不绕过保护；本轮没有声称对任意工程通用。
4. 隔离 Host 已在 Seatbelt 内，macOS 不允许再次应用沙箱。本轮测试夹具只将同一命令执行器放到
   启动器的兄弟进程，通过继承管道传递固定白名单命令；每条命令仍从启动即受上述更严策略约束。
   Host 原 sandbox.sb 未修改，无新增网络端口或宽权限兜底。这是隔离测试夹具，不是产品后台服务。
   产品默认直接启动受限命令；如果 Host 本身受不兼容的外层沙箱限制，明确失败，不自动部署该夹具。

## 五、验收不能外推的范围

- 原生子代理、失败重试、上下文压缩和安全断点恢复已有实际 Host 合成场景；具体双端最终结果以仓库外本轮报告为准。
  这不覆盖任意第三方插件调用、任意 Shell 子进程逃逸或所有故障无感恢复；未知副作用仍需要任务级核对，不要求用户修复 Session。
- 原生四入口合成调用和 DirectLink 验收不等于真实飞书／钉钉、外部模型长期业务验收。
- 工作台新增整体状态／报告数据投影，不代表 2.0 全部界面接线或视觉验收完成。

## 六、安全表述

云端宽文件权限意味着任意程序可使用执行账号的 OS 权限。
命令／路径检查只拦截明确表达的风险，不是能够识别编码脚本、间接调用及任意程序意图的通用防线。
任务规则用于约束行为，OS 账号和运行部署保护用于限制实际影响；二者不可混为一谈。
本次隔离测试的外层保护始终保留，但其测试证据不能外推为生产账号的权限事实。

不修改第三方代码，不以 full／partial 标签替代实际验收，不关闭正式或隔离环境保护。
历史原生沙箱探针与基础 24 项测试见仓库外 r3-foundation 报告；它们不代表本次全部执行集成完成。

## 七、配置示例（开发开关默认关闭）

执行端 `managedExecution.endpoint.commands` 是人工维护的固定命令表，例如：

```json
{
  "commands": {
    "test": {
      "executable": "/absolute/path/to/node",
      "args": ["--test", "--experimental-test-isolation=none", "test.mjs"],
      "timeout_ms": 60000
    }
  },
  "search": {"credentialRef": "DEEPSEEK_API_KEY"}
}
```

示例路径必须换为执行端实际可执行文件，不能指向任务副本内的可替换程序。
任务 `task_execution_prepare` 的 `commands:["test"]` 和 `search:{scope,model_policy,max_requests}`
仍需任务级批准；配置功能可用不等于所有任务自动获准。不得在配置中填入真实 Key。
