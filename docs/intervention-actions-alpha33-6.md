# 第05步：异常核对与受控处理

候选 `0.33.0-alpha.6`。仅隔离验收，不代表正式部署或发布。
本轮把已接受的异常预览接到自有工作台与持久账本；保留审批、异常处理和执行之间的边界。

## 用户操作

以“资料分析与整理”为例：

1. 选择任务，在“待你处理”点击“核对原因并查看建议”。展示缺报告原因、已保存检查点、原批次已用／上限。
2. 写下完整意见，例如“只用已有资料，不重新检索，报告分成两段”。点击“形成补充报告建议”只生成预览，不执行。
3. 建议明确展示原模型、材料范围、额外一批及最多六次请求。返回修改后重新形成建议；新建议会使同一窗口的旧待确认建议失效。
4. 复用第03—04步的已有 IM 窗口身份。首次通过已绑定机器人确认，短时有效窗口可逐项处理其他任务，不重复注册、不绑定设备。
5. 点“确认这份新建议并排队”，才记录明确处理凭证并排队。旧批次结束但不删除，旧预算保持不变。
6. 手动刷新查看排队、执行、完成及已登记成果。记账不等于开始，结束不等于任务成功。

不再继续时，点“查看结束范围”，核对后“确认结束本批次”；在途未排空时显示等待排空。
选择“稍后处理”只保存意见，不暂停其他工作。配置不全等情况可“请求维护处理”，明确显示尚待维护，不伪装自动修复。

## 动作范围

| 状态 | 本轮可用出口 | 不允许的替代动作 |
| --- | --- | --- |
| 当前独立只读任务缺报告／输出上限／预算耗尽 | 新建议、结束批次、稍后、维护请求 | 重置旧次数、自动重试、增加开发权限 |
| 当前独立只读任务待输入 | 补充信息，核对一批新报告建议后确认；或结束 | 把普通回复投给其他任务／更换模型 |
| 暂停的独立只读批次 | 只用已保存材料形成新建议；或结束 | 继续执行旧任务中的未核验操作 |
| 缺凭据、版本不符、未知执行结果 | 登记维护请求；符合独立只读范围时可结束 | 猜测配置、自动改模型、清锁重试 |
| 开发／提交／推送、A2A、共享工作流、定时计划 | 持久意见与维护请求，保留专门门禁 | 以子批次恢复绕过父级共享预算或写入审批 |
| 通知发送结果未知 | 明确结束该通知的人工跟进；或继续维护核对 | 自动重发、写成已送达／已读、取消整个任务 |
| 历史／缺失来源 | 保留意见并请求维护核对 | 依据过期列表直接执行 |

额外报告批次的固定硬边界：**1 批、最多 6 次模型请求、每次最多 2048 输出令牌**。
不重置旧预算；沿用该任务精确模型策略，无默认模型或静默回退。
保留最初任务约束、历史补充意见和此前报告材料；仅复用原批次保存的检查点和资料内容，不搜索、不读取新文件，材料超限则拒绝建议而非静默截断。
模型产生的报告是否符合内容要求仍需成果验收；本轮不承诺所有任意意见都可在这些硬边界内实现。

## 运行时接线

| 模块 | 职责 |
| --- | --- |
| `bundle/intervention-actions.js` | 来源核验、建议与完整意见、身份复用、持久操作、状态查询 |
| `bundle/intervention-job-control.js` | 同一 jobs 事务结束旧批次并创建最多一个确认过的新批次；保留预算与证据 |
| `bundle/task-interventions.js` | 原有来源观测历史及处理记录的只读投影 |
| `bundle/task-board.js` | 手动读取当前处理进度，不把历史回执当实时状态 |
| `bundle/job-version.js` | 新补充批次采用执行协议 `0.33.0`；旧阅读器不得静默执行 |
| `bundle/task-envelope.js` / `bundle/task-worker.js` | 保存材料专用上下文；原任务仅作约束背景，不重做原任务 |
| `ui-source/intervention-action-view.js` | 具体任务内的核对、意见、新建议、明确确认、查询原操作 |
| `ui-source/approval-workbench-client.mjs` | 同一窗口身份、独立操作 ID、结果未知时只查原操作 |
| 全局规则及 `task-sidebar` / `task-approval` Skill | 解释操作边界，不代替插件门禁，不覆盖用户规则 |

浏览器方法 `intervention-action-{inspect,prepare,confirm,status}`，经当前 Host 的 Origin 核验，
再通过自有双端协议映射为 `intervention_action_*`；必须协商 `intervention_actions:1`。
不注册为模型工具，不降级到旧 `job_control`。工作台身份与方案审批共用，不新增通行密钥或账户。

## 安全与恢复

- 当前任务修订、来源记录、原始 job、材料、预算及协调状态进入建议指纹；确认前重新读取身份与源事实。
- 确认阶段还重新核对其他活动批次和在途排空；有条件意见形成新建议，不能执行旧建议。
- `intervention_operations` 先持久化确认凭证；jobs 事务使用唯一原操作号写入 `controls` 回执，原批次取消和新批次创建原子完成。
- 跨库崩溃不自动重放：若原操作已有精确匹配回执，只读恢复结果；无法证明则保留待核对。
- 暂缓／维护只写本项目处理账本；通知结束调用既有 `NotificationReview`，不修改平台发送证据。
- 同一操作重复确认返回同一结果；新的意见须重新预览。失去页面不自动提交，旧端不支持时明确关闭新动作。
- 新补充批次若执行中断，已消耗 1/1 次则待核对，重启不赠送第二次执行。
- 本轮没有创建开发审批、写库授权或 Git 操作，也没有修改第三方代码。

## 回归证据

### 定向自动回归

37 份具名安全测试文件：**674 项，673 通过、1 历史跳过、0 失败**。
不是所有历史测试，也没有通配运行含 Git 写入的用例。
覆盖新建议、完整条件、过期／修订／身份撤销、幂等、并发状态变化、预算保留、在途排空、通知未知、
崩溃前后核对、旧执行协议拒绝、两端能力、浏览器来源保护、原审批与通知、规则安装保护及原生只读 worker。

### 官方 Host 与真实浏览器

- 本机新建两套官方 DSH `0.2.1-rc.3` Web Host，分别模拟 local／cloud 角色；独立 home、配置、状态和端口。
- 两端原生 standard／ptc／cordis／minimal 模式分别加载 85／85／88／3 个工具。
- 浏览器完成：核对 → 完整意见 → 返回修改 → 新建议 → 真实测试 IM 身份 → 工作台明确确认 → 云端独立 worker → 成果登记。
- 执行使用 **零模型探针**，在真实独立 worker 生命周期内写一份自有报告并结束；不是模型内容质量或真实 ECS 验收。
- 同一已核验窗口继续完成结束批次、稍后和维护请求；没有第二次身份跳转。
- 身份确认由用户授权的浏览器代输入，消息来自真实飞书测试机器人私聊；不是本人手打业务审批。
- 两端正常重启后，任务、审批、处理操作、身份、job、run、预算及原用户规则哨兵逐表／逐字节保持，无新增 job/run 或重试。
- 临时证据、凭据及运行状态均仅在私有隔离目录，不进入导出快照。

### 界面核对

| Before | After | Why |
| --- | --- | --- |
| 异常只有“查看原因” | 任务内核对、意见、建议及独立确认按钮 | 用户无需猜下一步或填写内部编号 |
| 状态说明与操作分离 | 隐去重复的通用下一步框，保留当前建议与影响 | 减少重复说明占用 |
| 意见直接变成继续 | 完整意见预览，修改使旧建议失效 | 不丢失条件、不执行旧方案 |
| “结束”含义模糊 | 本批次／通知跟进分别说明，排空单独展示 | 不把结束当成功或全任务取消 |

保留浅蓝白色、自有角色图、既有按钮与焦点样式；只按用户动作读取，不新增自动刷新。

## 限制与后续

- 本轮未在真实 ECS、原生 Desktop 容器或 Windows 上重新执行；不宣称跨平台真机回归完成。
- 本轮新增异常动作的权威结果在工作台；没有把维护请求自动发送给某个管理员，也不把它冒充原审批账本回执。
- 工作流／定时计划的整体恢复、开发和交付异常仍由各自专用流程处理，不能套用只读单批补充。
- 正式部署、模型实测、完整真实 IM 共载与全端验收留到第07步统一确认；本轮不使用日常配置。
- 下一步第06：成果入口、受控下载和对话查询核对；再进入完整隔离回归与单独正式切换确认。
