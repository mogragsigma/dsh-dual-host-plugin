## 选择与边界

用户在导览 3/6 选择本地或云端机器人，然后选择该端公开 IM 接口已保存的私聊或群。
确认保存后，该端作为默认交办入口和云端新定时任务的结果返回端。
机器人负责发送给用户／群，而不是机器人把自己当收件人。无需手输 bot ID 或 chat ID。
选择不关闭另一端原生 IM，也不截获或改写普通聊天；实际接收仍由官方 IM 插件承担。

- 本地端：Mac 离线时通知排队，云端工作继续；恢复先核对原发送记录。
- 云端端：云端机器人直接通知，不依赖 Mac 在线。
- 未配置可跳过，未确认不启用；所选端不可用时说明原因，不自动借用另一端机器人。
- 仅策略生效后新建的云端定时任务继承；立即任务和历史任务不会被追溯绑定。
- 单任务明确指定或关闭优先。默认值改变不挪动历史任务收件人，也不覆盖逐任务设置。
- 默认结果／异常摘要不授权上传所有附件、审批、开发、commit、push 或发布。

## 模块和持久状态

| 位置 | 责任 |
| --- | --- |
| `ui-source/onboarding/notification-defaults.jsx` | 第 3 页选择、手动读取、预览、确认、已保存状态与同步核对 |
| `bundle/onboarding-notification-defaults.js` | 本地导览授权存储；本端公开 IM 发现或受管云端发现；并发、过期、目标身份校验 |
| `bundle/notification-defaults.js` | 云端策略权威、版本约束、任务创建时捕获策略、定时调度时继承 |
| `bundle/task-notifications.js` | 原通知队列与发送链路；显式关闭、继承来源、策略失效和本地同步钩子 |
| `bundle/index.js` | 延迟任务与 trigger 创建后接入继承，不改变模型或任务预算 |
| `bundle/onboarding-host.js` | 公共 RPC 与现有 tick 接线；不启动第二个 IM 消费者或新计时器 |
| `bundle/onboarding-cloud-operation.js`、`onboarding-handoff-remote.js` | 受管云端公开目标发现，严格绑定归档契约与目标 Host |
| `bundle/link-contract.js`、`compatibility.json` | `notification_defaults: 1` 与 `onboardingNotificationDefaults: 1`，旧端缺能力明确拒绝 |

导览授权使用公开 credentials 服务的独立 grant：
`dsh-task-gateway/onboarding-notification-default-v1`，不写入普通草稿，不存机器人密钥。
grant 区分 owner、revision、operation 与目标快照。策略保存成功但配对未完成时显示待同步，不能称已生效。

云端 SQLite 新增 `notification_default_policy`、`notification_default_history`、`notification_default_tasks`。
逐任务绑定沿用原表，来源明确标为 `onboarding_default`；不伪造人类聊天引用。
未收到可靠发送回执时沿用原通知恢复规则，不盲目重发。

## 安全及恢复

预览和执行均校验实际机器人账号指纹、已保存目标摘要与目标端身份。
执行只接受未过期的原计划及当前修订；结果未知保留操作，先查询原记录。
策略按 owner／revision 幂等同步，云端只接收已认证本地节点的发布；模型工具没有默认授权写入口。

更改或停用默认值会取消旧继承的 queued／leased 通知，并禁用其绑定；不会重定向已排队消息。
已进入发送的消息可能已被平台接受，不能承诺撤回；显式逐任务绑定保持。
记录禁用状态也避免旧版读取器在回滚后误把旧继承授权当作启用。

云端桥的归档源码新增后，受限 SSH 命令长度从 24,000 调整为 24 KiB（24,576 字节），
并减少 loader 引号转义。仍有固定限额，传输原归档字节，不换控制器、不在参数中传凭据。
此变更需单独传输回归，不归类为 UI 调整。

## 界面与验证

| Before | After | Why |
| --- | --- | --- |
| 固定由本地机器人作为默认端 | 本地／云端下拉选择，确认后生效 | 遵循最新需求，不用机器人名称猜测角色 |
| 机器人账号可能被误当收件人 | 分开显示所选端、机器人与返回对话 | 收件人必须是真实私聊或群 |
| 空白 Host 可能没有可用目标 | 明确显示无已保存对话、不可用原因和手动读取 | 不静默借用另一端或自动发送 |
| 保存后容易误以为已启用 | 区分已保存待配对、同步未确认、已同步云端 | 界面不能夸大实际状态 |

复用现有浅蓝白色、问号说明、按钮样式与手动刷新，不新增自动轮询或装饰动画。

已通过的专用 15 项测试覆盖双端选择、默认继承、显式覆盖／关闭、旧任务不追溯、
周期触发、目标漂移、缺能力旧端、未知保存及 loopback RPC 断线／重启去重。
这里的 RPC 和发送 SDK 是隔离合成夹具，不是实际飞书送达证据。

当前 Mac 定向合集为 300 通过、0 失败、51 跳过；上述专用测试与其重叠，不合并计数。
跳过项含非 Linux 平台测试和历史 S65 UI-only 断言，不作为候选能力通过证据。
当前源码 bundle 与 alpha.3 新清单逐文件一致；历史 alpha69 清单未修改。

全新官方 Mac Host 已验证第 3 页控件与空配置状态；另一个 alpha.3 Host 已完成规则保护追加。
ECS 新根目录只完成受管归档与 runtime 预览，尚未启动新云端 Host。
真实双端机器人收发、完整六页闭环、模型定时任务、成果入口及卸载重装仍待验收。
S67 已另获正式环境部署与必要重启授权；实际部署、真实收发和重装结果以 S67 证据为准。
仍不得重放旧任务或仅凭隔离回归声称全链路已交付。

## S67 正式切换前补充

- 已配置双端通过当前认证 A2A 链路发现云端公开 IM 目标，不要求伪造新建 ECS 归档。
- 能力协商新增 `notification_default_peer: 1`；候选按云端实例固定，重启或缺能力时拒绝，不换端兜底。
- alpha.4 的完整前置回归发现全局规则模板超出 12 KiB 上限，导致两端各 12 项失败；没有部署。
- alpha.5 将新增说明合并入既有通知段，模板为 12,106 字节；不扩大上限、不截断用户规则。
- alpha.5 Mac、Linux 保护性安装和维护定向回归均为 206 通过、0 失败；扩展回归继续中。


## S67 正式环境增量证据

- Mac／ECS 均完成 alpha.6 备份切换，原配置、用户规则、历史会话和业务表逐项保留。
- 两端真实飞书私聊收发通过；云端新定时任务以自然语言选 DeepSeek Flash／high，
  持久批次预算为 1，延迟 90 秒执行 1 批，报告登记后自动通知在云端私聊可见。
- 默认绑定来源确认为 `onboarding_default`，没有模型手工补建逐任务绑定。
  通知账本证明 SDK 接受；另有真实聊天可见证据，不冒充用户已读或平台消息号回执。
- 初次验收发现原生 `task_schedule` 未传预算会沿用旧协议 4 批；该新测试任务在执行前取消，
  尝试次数 0。alpha.6 强制原生工具填写并校验 `max_runs`，旧协议默认和重放指纹保持。
- 两端定向安装维护回归各 208 通过，预算／通知等定向回归各 32 通过；有重叠，不相加。
- 本地默认入口在真实 Desktop 导览 3/6 完成选择、预览和确认，双端同步成功；
  离线时云端完成并排队，恢复后本地私聊可见；再次重启后原投递记录不变，attempts=1。
- 当前正式安装是历史手工入口，公开包管理只识别为 `entry_only`，不是官方受管 bundle。
  产品自卸载因此正确拒绝推断包归属。后续需按冻结清单保护性迁移，不伪造包归属，
  不把手工恢复路径冒充新用户官方包卸载流程。


### alpha.7 原生后台接线修复

真实 admission 的活动标签白名单遗漏了 `notification_defaults_sync`，导致 alpha.6 后台通知退出。
修复只增加这一固定标签，保留停机围栏和活动计数；没有重跑 worker 或改写队列结果。
新增组合测试接入真实 `createOnboardingService`、真实活动门禁及通知队列，修复前 2 项失败，
修复后 Mac／ECS 各 54 项通过；两端安装维护定向回归各 208 项通过，统计有重叠。
正式双端 alpha.7 已完成原队列补发及再次重启去重验证；未宣称六页卸载重装全部完成。
