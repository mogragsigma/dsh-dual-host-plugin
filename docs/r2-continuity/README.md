# R2 单用户任务连续输入

隔离候选 `0.34.0-alpha.2`，未合并／推送／发布；当前正式版仍为 `0.33.4`。

## 启用与边界

两端自有 Gateway 配置 `continuity: { enabled: true }` 后声明 `continuity:1` 能力。
默认关闭；旧任务不自动迁移，新交办的原生任务才有连续输入合同。
已存新合同的云端禁止直接关闭开关，以免绕过持久暂停／停止。
不能直接回退旧插件来继续运行这些任务；旧插件不认识新执行围栏。

复用 DSH Host 准入及 dsh-im 所有者／白名单，无新增个人认证、第二 IM 消费者或群内机器人接力。
四类入口均调用原生 DSH 任务工具。IM 缺少可靠回复链时走任务目录，不读第三方私有数据库。
IM 新建机器人默认可能是 open，不能将“已有所有者”误当作群访问仅本人；需保留明确白名单配置。

## 记录与接口

- 同一云端 Coordinator SQLite 内保存任务关联、连续输入、交回和任务控制，不建第二任务库。
- 原消息身份是 Host 角色／Session／Message 的组合；原文和摘要分开。
- 同消息重试去重；不同入口相同文字不合并。修订与任务控制分别进行版本检查。
- 输入保存不增合同修订或批准，不清零预算；`follow` 负责跟进，`reference` 仅作材料。
- 精确成果 ID 验证属于该任务；不默认最近版本。
- Worker 通过绑定当前运行的工具按页读取。新输入可用原生非唤醒 `inject` 提示运行中的 Worker；
  提示本身不算投递，真正工具返回才记 `delivered`，永不自动记已读／已落实。
- 全部责任方交回后才允许同原事件重新归属，不投回已交回任务。
- 暂停／停止先写持久围栏，再收拢当前 jobs；恢复只恢复本次暂停的 jobs，不覆盖独立暂停。
- 执行未收拢仍显示 `draining`；停止终态不能由输入、查询、旧恢复或重启复活。
- 入口发送失败保留同请求于 Gateway outbox；未知结果重查原请求，不伪造云端受理。

新增原生工具：`task_resolve`、`task_followup`、`task_followups`、`task_lifecycle`、
`task_followup_reroute`、`task_thread_unlink`、`task_decide`。
Worker 新增 `worker_task_inputs`、`worker_input_handback`，不改变普通 DSH 工具集。
任务面板复用现有整体状态呈现；`task_status` 和连续输入查询提供实际回执。

## 阶段约束

自然语言理解由原生会话模型完成，不新增常驻分类 Agent；模型语义判断不是硬安全沙箱。
四入口并不意味着复制全会话或默认广播四端。普通查询不启动 Worker。

R2 不实现 R3 长任务、受管本地 A2A、3＋1、归档恢复，也不实现 R5 CLI 研发。
旧任务的已有 A2A 合同保留；新 R2 任务暂不调用旧 A2A 执行合同，明确返回执行适配尚不可用。
旧任务的短批次、审批和交付规则保持；新任务的研发／交付执行返回适配未就绪，不要求补配 IM。
完整执行器替换不在本候选范围。

## 验收

`python3 scripts/run-r2-regression.py` 必须经隔离启动器运行。
它是确定性合同测试，不代表真实飞书／钉钉消息或真实模型理解已验收。
完整既有回归须在 ECS 独立网络命名空间执行；本地不为随机端口测试放宽生产端口保护。

## 任务权限与 IM 权限解耦

- 新任务复用现有方案／决定账本；原生入口的完整用户意见与确切方案修订、哈希、前次决定绑定。
- 任务工作台复用 Host 已登录访问、同源检查与原操作回执，不再要求 IM 身份租约。
- `task_native_decisions` 仅保存决定来源与内容审计，不颁发个人凭证。旧账本 `credential_id` 字段
  中的 `task-native` 只是兼容路径标识，不是令牌、注册账号或额外认证系统。
- IM 所有者／白名单仅由上游 dsh-im 用于消息准入；本插件不将其解释为 develop／push 等权限。
- 新任务不排队发送旧 IM 方案、不依赖旧 IM 证明，也不因机器人更换而撤销决定。旧任务原规则保留。
- 新决定仍受任务、方案修订、有效期、授权范围、上一决定、暂停／停止与执行器能力限制。
- 原操作在记账后失去响应时，工作台查账补齐回执，不生成第二次批准；端间 outbox 仍按原消息去重。
- 原生会话语义复用 DSH 当前模型；工作台先复用现有确定性规则，不能可靠解释时待澄清，不调用旧 IM 分类器。
