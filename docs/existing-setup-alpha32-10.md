# 既有双端六页复用确认

## 结论与范围

`0.32.0-alpha.11` 已部署到正式双端并完成既有配置六页复用、真实任务与成果访问。
本分支不把旧 Host 当作导览新建实例，不复制密钥、不认领原生配置、不增加业务执行权限。
全新用户初始化与既有配置复用明确分开；正式证据和保留限制见
[正式双端收尾验收](production-acceptance-alpha32-11.md)。

此前输出额度耗尽的失败任务不重试、不改预算、不通过新任务消除历史失败。

## 六页与模块

| 页 | 用户动作 | 实际行为与边界 |
| --- | --- | --- |
| 1 | 手动核对既有双端 | 认证直连、实际实例和目标端路径，不要求 SSH 私钥或再建 ECS |
| 2 | 输入云端模型简称，必要时自然语言澄清 | 目标端公开目录和路由校验，high；不推理、不改任何默认模型 |
| 3 | 可选复用 IM 或沿用原配置 | 核对现有默认通知与云端权威账本；修改默认端仍单独预览确认 |
| 4 | 可选填写 Gitee 任务成果仓库 | 云端固定 API GET 核验默认分支和基线，不克隆、不写入、不创建绑定 |
| 5 | 核对托管规则与 Skill | 只承认真实安装器账本；保留用户原文，缺失或漂移阻断确认 |
| 6 | 预览并明确确认 | 重新读取两端证据，仅保存一份自有复用确认记录 |

跳过 IM、仓库只表示不纳入本次复用确认，不停用功能、不解绑历史任务。
模型和路径清单不等于真实推理或会话加载；IM 数量和默认账本一致不等于送达。

| 模块 | 作用 |
| --- | --- |
| `onboarding-existing-setup.js` | 复用选择、证据收敛、预览、CAS 确认与未知保存屏障 |
| `onboarding-existing-host.js` | alpha.9 的双端只读观察与实例校验 |
| `onboarding-host.js` | 原生认证端点和公共服务装配；受维护屏障约束 |
| `index.js` / `link-contract.js` | 新增可选 `onboarding_existing_repository: 1`，只允许固定 Gitee 读取 |
| `ui-source/onboarding/existing-setup.jsx` | 独立六页复用表单、跳过、说明、确认及历史回执 |
| `ui-source/onboarding/app.jsx` | 选择原新环境流程或既有配置分支；离开前提示未保存输入 |
| 全局规则 / `task-onboarding` | 复用非安装归属、非执行授权；配置、加载和验收分别记账 |

## 持久化与失败处理

原 `onboarding-draft-v1` 结构不变。新记录使用官方凭据服务的自有命名空间：
`dsh-task-gateway/onboarding-existing-setup-v1`，类型为 grant，不含凭据值。
它只存选择、裁剪后的路径／规则／目录证据、模型策略、可选通知和仓库元数据。
不记录机器人 ID、Key、原始配置、会话正文或访问 Cookie。

- 每次预览有效期为 5 分钟，确认前重新核对；实例、模型、规则、通知或仓库基线变化即拒绝。
- 保存前消耗内存计划，持久写入用修订号 CAS；并发页面不能覆盖先完成的确认。
- 保存超时或丢失响应只查询原操作，不能自动重放。
- 显式关闭待决时仅写入修订屏障，不清除实际配置；已确认操作与旧核对发生竞态时拒绝旧屏障。
- 重启后只能读取历史回执，不能将它当实时就绪状态；新预览重新取证。
- 服务销毁、维护中、旧对端缺能力时关闭对应路径，不降级到缓存、另一端或任意 SSH 命令。

## UI 回归与调整

| Before | After | Why |
| --- | --- | --- |
| 新复用面板未套用连接面板类，按钮贴边 | 使用既有连接面板与 16px 动作间距 | 延续浅蓝白样式，避免边界相接 |
| 窄屏页头操作可能逐字换行 | 自有分支页头可换行，按钮文字不拆分 | 保持可读和可点击，不修改业务逻辑 |
| 离开复用分支可能直接丢失填写 | 明确提示未保存输入，用户确认离开 | 不让切换入口冒充保存成功 |
| 只显示用户输入的模型简称 | 最终预览显示解析后的实际模型 | 确认目标准确，不要求用户填写内部编号 |

所有查询由按钮触发，无定时刷新。沿用角色形象、问号说明、必填提示和 1/6 页码。

## 验收分层

- 单元与回环：预览零写入、选择性 GET、无仓库绑定、身份漂移、并发、未知保存、屏障、历史回执。
- 官方 Host：全新隔离的原版 rc.3 进程和合成目录，真实原生 RPC、双端托管安装、复用确认、重启读取。
  没有模型请求、机器人凭据或生产任务；不能称作真实模型／IM 验收。
- 浏览器：明确标识的模拟页面，六页、自然语言澄清、选填与跳过、问号、未知保存查询及宽窄屏。
- 正式环境：ECS 已备份切换，公开维护接口升级托管规则；43 个会话及全部业务数据表保持。
  Mac 仍为 alpha.7，已通过旧端到新云端的认证工作台读取；六页正式复用确认仍未完成。

## 回滚边界

只新增自有记录，不迁移任务、审批或原草稿表。回退 alpha.7 时保留此记录，不改数据库或复用旧确认。
规则／Skill 已有真实托管归属，升级及回退必须走公开维护接口；禁止旧中文标题替换脚本。
插件本体仍可能是手工 entry 接线，不得伪造官方包的卸载归属。

## 正式云端分阶段切换

2026-10-25：原 37 项协议能力与 109 个方法保持，仅新增可协商能力。

安装账本仍含 20 文件，用户原文 85 字节保持。再次正常重启后，43 个会话、86 个历史文件
及业务数据库各表均未变化，原生 IM 已连接。Mac alpha.7 到云端 alpha.10 的认证只读查询通过。
未新建任务、重试旧任务或增加写入授权；既有开发总开关保持原配置，不将其误报为关闭。
完整双端正式验收仍待 Mac 切换、六页复用和后续只读闭环，不以分端成功代替。
