# 大肥鱼2.0安装与启用

> 2.0.1安装说明；发布状态以包来源回读为准。以下是公开的原生DSH配置路径，不是灰度脚本。
> 包安装、配置保存、运行时已加载、双端已连接和任务已执行是不同状态。

## 一、安装与版本

只从仓库根包安装。准备期使用已核验的tgz；发布后才能改用registry版本。
在每端自己的DSH、HOME、DSH_HOME、DSH_AGENTS_HOME和实际profile中执行：

```sh
dsh plugin --profile YOUR_PROFILE add /absolute/path/dsh-dual-host-plugin-2.0.1.tgz --allow-build=koffi
```

不要使用正式profile做测试；不要向插件内另装DSH依赖。独立新建Host模板锁定0.2.2-rc.1，
不代表安装插件会升级现有Host。宽兼容准入与逐版本实测不同，见根兼容声明及验收记录。

## 二、使用原生profile配置启用

随包的 `configuration-v2.json` 提供local/cloud两份原生Cordis patch数组。
在实际profile的 `cordis.patch.yml` 中合并对应数组，不覆盖其他插件设置，不重复插入同名工具插件。
可用JSON格式保存该YAML文件；保留安装器生成的插件包选择及默认bundle。

1. 两端选定同一个PAIR_NAMESPACE。STATE_DIR分别指向各自独立、私有的状态目录，不能交换或共用数据库。
2. TOKEN_FILE是本端私有JSON文件路径，权限0600。云端包含不同的localToken、cloudToken；
   本地只需同一个localToken。每个令牌至少32个随机字符，不把令牌放进聊天、任务或配置示例仓库。
3. 三个示例端口需确认空闲。云端Gateway仅监听127.0.0.1；跨机器用既有SSH转发将本地coordinatorUrl
   指向云端回环端口，校验SSH主机身份，不改成公网明文监听。转发端口不与本地Gateway端口相同。
4. 云端endpoint只在云端配置。本地不配置执行endpoint，不回退为本地worker。
5. 如需指定任务默认模型，在managedExecution中增加defaultModel对象，provider/model取云端实际目录。
   不填写则沿现有DSH默认；显式任务模型可覆盖。API Key仍由DSH原生凭据配置，不填进模板。
6. 安装自有规则/Skill沿既有安装入口进行，预览冲突后确认，不能覆盖用户规则。
   普通聊天保留DSH原生能力，新任务才进入云端受管执行。
7. 按当前Host方式正常重载。通过工作台和 `task_identity`、`task_source_capabilities`、`task_results`
   观察实际服务；在本地对话交办小任务，核实云端进度与成果，不能只凭配置文件存在宣称启用。

无IM也可完成本地DSH交办。可选IM由dsh-im原生配置所有者/白名单和机器人连接；
本地机器人进本地DSH、云端机器人进云端DSH，不新增消费者，不从IM权限推导任务权限。
旧向导的“只读任务Worker”属于历史受管运行时，不是2.0充分自主云执行；不要同时启动两套Gateway。
切换已有实例涉及存量迁移，须按单独升级方案进行，不能直接套用新建配置或另建空库冒充迁移成功。

## 三、来源与主动策略

默认sourceIntake关闭、sources为空；任务运行不以来源接入为前提。
如需接入，复制selectedSource示例到云端sources，替换真实仓库URL、不可变repository_id、
匹配namespace、scope及最多8个Issue编号。示例42和IEXAMPLE不是可运行的测试凭据。

私有仓库读取沿既有repositoryAccess凭据引用。先按DSH配置启用该来源并核对状态，再通过
 `task_source_status` / `task_source_control` 选择observe；auto必须由本人明确策略、范围、交付和本期新任务总数。
不能在安装配置中默认为auto，不代填总数，不重置旧周期。来源作者和内容不是用户授权。
接入/来源启停、处理模式、策略撤销分别操作；停止接收不意味着撤销全部既有任务。
此路径不订阅全仓、评论或Webhook；缺配置或读取失败应显示未连接/具体错误，不冒称在线。

## 四、文件与故障边界

成果登记、不可变快照及任务内查询由云执行提供；发送还需明确目标与实际通道能力。
跨端文件队列和IM发送并非只靠上述基础模板即全部启用，应在现有文件/IM配置中显式配置并验收。
本地路径不会自动上传，缺资料需明确提供；不能开放整个电脑或默认复制目录来消除报错。
跨端文件新配置默认32MiB，可显式配置，现有缓冲实现技术上限512MiB；这不是该大小性能保证。
旧隐式/显式配置不自动扩大。已收妥文件按原大小核验，不因新传输上限降低而误报旧成果不可用。
双端与云IM的3,420,279字节ZIP已按哈希核验；本地IM大ZIP受网络超时影响，首发按批准边界简化，
已有小文件通过不代表本地大文件通过。平台拒收、缺失和未知发送回执必须如实呈现，不能重复派工代替补交付。

身份/令牌不匹配、缺模型服务、来源未配置、SSH未连接应先修复对应配置，不清库、反复建任务或扩大权限。
会话归档由系统处理，不自动删除；停止的任务不因重新连接或升级恢复。
任务调用次数不设插件上限，也没有统一300秒或两小时许可重批；服务商限流、技术超时仍然存在。

## 五、已有实例升级与恢复

不要将新建示例直接覆盖已有profile、令牌、规则或状态目录。先检查活动任务并排空Host，
确认目录无占用后备份实际配置、数据、规则/Skill及插件版本，校验备份后再走原生安装器。
旧任务、失败、成果、原发送回执保留；升级不复活停止任务、不静默开启来源auto、不重置期总数。

2.0前向升级及独立快照恢复已有隔离验证。不要求兼容回退0.33.4二进制，不保证其可读取含2.0新任务的库。
需要恢复时使用经验证的2.0版本与经校验快照，先在独立目录核对，保全当前新数据；
不能用旧库覆盖新写入，也不能把恢复数据库当作撤销已经发生的外部发送或Git操作。
管理员绕过维护流程手动降级不在安全保证范围内；正式部署、恢复或数据删除须当次明确授权。
