# 双端配置导览

- 从单一「大肥鱼bot」进入「配置导览」。新安装无网关配置时显示六页导览，不创建网关数据库、任务或消息消费者。
- 六页为连接云端、模型、聊天与审批、成果与仓库、方案、配置与验收。页码与已填写数量不同；跳过可选项必须标明未启用。
- 默认提供导览能力，不自动执行；经独立主机信任确认后可手动执行只读 SSH 预检。SSH 连接通过不等于模型、仓库、审批或初始化通过；完整导览初始化尚未接通；隔离源码、运行时和原生 Host 准备须分别确认并查看真实回执。
- 普通字段只填写凭据引用名称；Key 仅可进入独立的受管凭据窗口，不可进入聊天或草稿。不收集私钥原文，不复制密钥或修改现有模型。新任务模型以后按目标端实际配置解析，不强制 provider。
- 路径取当前 Host 的显式根配置、进程环境与系统 home。Mac/Linux/Windows 分别解析；云端必须在实际服务账号下独立检测，不能以 SSH 用户 home 替代。
- 多个全局来源、关闭默认扫描、自定义路径、符号链接、只读文件、编码或同名冲突要明确报待核对。候选路径不等于已加载，检测不赋予安装权限。
- 已有 AGENTS.md 经独立预览与确认只追加自有受管区；不存在再创建。升级仅限经清单确认的自有区块；内容改动、标记异常或并发漂移时停止。绝不覆盖整份用户规则。
- Skill 按自有归属与摘要清单保护；全局与 worker 专用分开，用户同名内容不覆盖。写入文件不等于加载生效。
- 官方 Host 的全局指令根来自该进程的 `DSH_HOME`、`DSH_AGENTS_HOME`，未设置或环境值仅为空白时回落到该进程 home 的 `.dsh`、`.agents`。导览里的候选配置不能改变官方指令加载器；Skill 提供方还可能逐模式设置自定义根或关闭默认扫描，必须分开核验。
- 官方 0.2.1-rc.2 隔离实测：标准、PTC、Cordis 模式加载全局规则与 Skill；最小模式原生不加载它们。不得为了让规则“生效”强改预置模式；也不得把本机实测当作云端、Windows/Linux 或其他版本的实际加载证明。
- 验收应记录官方提供方在实际会话作用域观察到的来源和加载结果；路径存在或导览的只读检测成功不等于该模式已加载，不等于模型已执行。
- 当前只在隔离测试环境运行，不使用日常 DSH 配置/会话/凭据；不可调用旧运营脚本来补做初始化。
- Gitee 是可选的用户 B 成果仓库；所有操作经 CLI/SSH/API。导览仅在手动核验时只读访问，无仓库任务仍保留成果介绍与执行会话。

## 本端保护性规则安装

- 无需隐藏测试开关；从当前 Host 的系统与环境解析实际路径。预览只读，应用须核对逐项计划并明确确认；现阶段仍只在独立 Host 验收，不动日常配置。已有隔离边界不能因配置不完整而退回默认路径。
- 第 5 页先预览逐文件计划，再单独勾选并应用。进入下一页的勾选不是安装授权；关闭页面也不是取消已提交事务。
- 预览 5 分钟失效；应用前重新核对快照，任意变化停止。只有唯一已有全局文件才自动选择，两份同时存在先选定，另一份保持不动。
- 用户原文、BOM、换行、权限保留；未知同名 Skill 或目录阻止，不覆盖也不自动改名。工作器专用 Skill 不混入全局。
- 持久备份与事务回执支持失败回滚。只撤销本事务且内容未被修改的文件；发现并发编辑保留现场、标记待核对。崩溃后显式核对并确认回滚，不自动继续安装。
- 已安装摘要一致则不重复追加；本期没有升级已有托管内容的能力。文件回执与会话加载证据分开，不能把安装成功当作初始化完成。


## 导览草稿与凭据边界

- 导览通过官方凭据服务管理自有槽位；保存草稿及写入 Key 均须用户操作，不自动读取其他槽位，不要求隐藏启用配置。
- 草稿不包含 Key、私钥或密码。不要要求用户把 Key 发到聊天或写进 AGENTS.md、Skill、仓库和诊断。
- 已保存不代表模型可用；预备云端槽位仍存于当前 Host，未传送到 ECS，未执行初始化。
- 草稿恢复不恢复审批、检测新鲜度或业务执行许可；并发冲突须核对最新版本，不覆盖用户记录。
- 官方默认凭据文件是权限保护，不是插件加密，也不提供与同账号智能体隔离的承诺。

## 云端连接、预检与计划边界

- SSH 只引用已有私钥路径或代理，不复制私钥，不修改日常 SSH 配置或 known_hosts；不得自动接受首次或变化的主机公钥。
- 网络扫描仅提供待核对的公钥指纹，经可信渠道核对并明确确认后，才允许固定主机身份进行只读登录。
- 连接记录保存不等于验证通过；结果未知时先手动核对状态，不盲目重发确认。地址或认证条件变化后，旧观察不能用于新目标。
- 预检只读取账号、运行时、目标目录元数据和可用空间，不读取其他 Host 配置、凭据、用户规则正文或进程环境；现有进程的发现不等于其工作区路径已核验。
- 新建独立 Host 的拟定路径来自实际远端登录账号；已有 DSH 的规则路径仍须按其真实服务进程单独核验，不能混淆。
- 预检观察 60 秒后按历史结果对待；安装计划 5 分钟有效，执行前仍须重新核对绑定、内容摘要和目录基线。
- 初始化执行器尚未完成。单独启用的源码准备接口须明确确认，仅写入归属可证明的新测试根；不安装运行时、不启动 Host、模型、IM、Git 或业务 worker。源码已准备不能写成“云端已初始化”。
- 发现未知已有目录、符号链接、来源不明的归属标记、旧运行时或权限问题时停止相应步骤，不覆盖，不把需要人工核对说成成功。

## 云端源码准备与恢复

- 导览默认展示准备与启动能力，但不自动执行；第 5／6 页分别确认，能力可用不等于获得写入授权。完整初始化仍待后续工作包接通。
- 准备前重新核对 SSH 绑定、目录基线、候选逐文件摘要和计划有效期。仅允许声明的发布文件，不传 node_modules、私有配置或凭据。
- 请求先记入官方凭据服务的自有事务槽位，再经 SSH 发送；事务证明只在受管槽位与 SSH 标准输入内流转，不进入命令参数、页面或日志。
- 远端归属标记和日志绑定事务、路径、目录身份、文件清单与进程身份，并校验签名。标记外观相似不是归属证明。
- 关闭页面、丢失响应或 Host 重启后，先核对同一原事务，不自动重发。归档的原始控制程序用于核对和回滚，不随当前候选变化而替换。
- 回滚须单独确认并核对当前修订号；执行进程未退出时不回滚。未知文件、额外目录、链接、正文或权限漂移均保留待核对，不用递归删除代替核验。
- 部分准备尚不支持自动续传；可以在进程已结束且归属、文件均一致时明确回滚。根创建后、归属标记写入前的异常须人工核对；不宣称所有崩溃都可自动回滚。
- 这些能力不授予业务开发、提交、推送或发布权限，也不代表操作系统账号隔离。

## 超时请求隔离与新目标

- 目录不存在不是原请求已终止的证据。只在原控制器语义已核验、用户明确确认后，使用原子且不可覆盖的阻断文件隔离原目标；不把隔离说成回滚或进程终止。
- 已存在目录、用户文件或未知标记不能替换成阻断文件。原请求已落下源码时，先使用原事务核对和保护性回滚。
- 阻断文件必须保留，并在回执中列出；不可把它当作普通残留删除。未来清理须有可靠停止证据和独立的精确清理计划，不能只依据等待时间或一次进程快照。
- 明确确认更换目标后使用新的实例标识。连接账号和已经核验的主机公钥保持不变；原绑定、事务证明与回执保存在本项目官方凭据历史槽位。
- 官方凭据键必须经公开 credentialKey 工厂构造，遵循 scope/id 两段规则；不能通过第三层路径组织历史记录。测试替身也必须调用官方键校验，且须经过真实 Host 重启验收。
- 只读核对超时后继续核对同一事务，不重发准备操作；准备请求延长限时不代表自动重试，也不改变开发、提交、推送或发布权限。

## 独立运行时安装

- 运行时安装另行确认，只使用源码归档绑定的官方锁文件与固定 registry；npm 不继承用户配置、代理、令牌或安装脚本，缓存及 HOME 限自有测试根。
- SSH 仅启动独立后台安装进程，持久账本先于启动；页面或主 Host 重启不重发安装。结果未知先读同一事务，无记录不能当作已回滚。
- 按内核启动标识核验 worker 和 npm 子进程；运行中禁止删除。停止仅对已核验的独立进程组，不按名称批量杀进程。
- runtime_ready 只表示锁定包安装通过，不表示原生 Host、全局规则、Skill 已加载；只有 nativeHostReady 且附实际模式上下文证据，才可声称独立 Host 与加载验收通过。
- 回滚核对安装后清单，拒绝删除新增、修改、替换或权限漂移的内容；这不是与同账号用户隔离的沙箱承诺。
- 大目录清理的回执丢失时不重发删除：先核对原实例、安装进程与 npm 子进程的内核启动标识以及目录缺失，再恢复回滚回执。单独看到目录缺失或旧回执的“空闲”字段均不足以确认。运行时移除尚未核验时，不回滚上层源码。

- 原生启动使用独立 profile、HOME 和工作区，仅监听回环；官方支持脚本须固定摘要，仅调整官方运行辅助文件的可执行权限，不改第三方源码。预置模式保持原生行为，最小模式不强行注入规则。
- Host 启动须先保存内核身份再放行；主控重启不重复启动。活动 Host 禁止回滚，停止后若文件变化则保留现场待核对。全局配置完成、A2A 绑定、模型与 IM 可用性仍分别验收。

- 使用官方 `--patch` 加载独立自有配置层，不覆盖官方 profile 默认配置；验收保留默认文件摘要。模式挂载回调不得把挂载句柄误作为会话创建事务返回。运行中回滚明确拒绝，不得误记为已执行或结果未知；官方凭据载荷必须能无损 JSON 往返，不能保存 undefined 字段。

## 六页导览的执行与恢复

- 第 5 页只预览并独立确认准备安装文件；第 6 页再预览锁定依赖与 Host 启动计划，另行确认。阅读说明、保存草稿或切页均不授权执行。
- 进入页面只读本地历史账本，不发 SSH、不恢复确认、不自动续跑；实时状态由用户手动刷新。旧回执、观察过期和未知结果不可显示成已验证实时就绪。
- 未知发送结果继续核对原事务，不能重新生成计划来绕过；有记录但未观察到远端进程不等于从未启动。停止、运行时回滚、安装文件清理分开确认，活动进程与漂移由服务端再次拦截。
- 原生 Host 启动只完成基础阶段；模型、IM、A2A、开发和 Git 写入仍未启用，不据页码或进度条宣布整套初始化成功。

## 专用 Node 准备

- 目标缺少适用 Node 时，可独立预览并确认固定官方版本；已存在系统 Node 时也可主动选择专用版本，不替换系统 Node。
- 首版支持 Linux x64／arm64、内核 4.18+、glibc 2.28+、Python 3.8+ 标准库；不满足时明确列出，不擅自升级系统组件。
- 官方包地址与 SHA-256 固定在自有发行代码中。只走 TLS 校验，不接受自定义镜像、重定向、任意包名或命令。
- 使用新建的专用 node 实例根；不修改 shell、全局 npm、日常 DSH、模型或系统服务。先校验完整包，再拒绝越界路径、硬链接、设备和未知成员。
- 确认请求先存入自有持久槽位；SSH 只启动独立 Python 准备进程。关闭页面或重启主控后只读同一账本，不自动重发。
- Node 就绪后重新生成云端安装计划并再次核验完整性，使用专用绝对路径；故障时不悄悄退回系统 Node。
- 停止、移除分别确认；按进程出生身份核对，不按名称批量终止。仍有独立 Host／源码引用或阻断标记时不可移除 Node。
- 移除按签名清单逐项核对，未知文件和漂移保留；共享父目录保留。负载清理中断可核对剩余已登记项，控制账本自身丢失不宣称可自动恢复。

## 已安装独立 Host 的重新启动

- 先停止本事务 Host、手动刷新并核对出生身份；预览重新启动计划后再单独确认。不是重装依赖，也不是重启整台 ECS 或日常服务。
- 重新核验自有归属、程序完整性、当前配置与数据快照。程序漂移阻止启动；允许保留的配置或工作区变化只计入计划，不自动纳入删除清单。
- 每次启动使用独立 nonce、进程出生身份、日志与原生模式回执。旧登录地址、旧就绪回执都不能证明新进程已经就绪。
- 请求意图先持久化；主控重启或响应丢失后先读账本、手动核对。未观察到本次请求不代表未发生，不自动重发、换计划或启动另一进程。
- 重启不覆盖默认配置、不重写用户全局规则或 Skill。就绪仅是基础 Host 验证，模型、IM、A2A、开发和 Git 写入仍须后续独立配置和授权。
- 旧版本归档不支持重启契约时明确拒绝，不能把新控制程序强套到旧事务。安装／重启控制进程异常退出的恢复须单独证明，不能把普通进程重启测试当作全部崩溃窗口已覆盖。

- 若启动 worker 异常退出，状态标为“需核对”而非成功。独立进程均已证明退出后，可单独确认将该次启动记为中断；这不重试、不删文件，仍需另一个新计划和确认才能再启动。没有本次远端意图证据的未知请求不可据此解锁。

- 原生验收会话仍遵循 DSH 的持久化生命周期，不假设取消创建就不落盘。每次重新启动只可登记该次随机 nonce、真实回执和启动前缺失证据绑定的 4 个零模型验收会话文件；签名增量清单与原安装清单分开保存。不得重扫并认领其他文件、扩大为用户数据删除许可或追认旧归档。
- 自有覆盖层固定专用 spill 根，不修改官方 profile 或停用原生清理。验收文件一旦被用户修改、增加子文件、替换、改权限或账本异常，仍须保留待核对；真实回滚和清理中断恢复须各自验证。

## 运行时清理中断恢复

- 初次回滚先核对全部登记文件，再持久化独立签名计划与有界删除进度；不刷新或扩大原文件归属。
- 使用 Linux 系统 flock 锁住既有归属文件，阻止并发修改；内核进程退出后才释放，不按超时猜测停止。
- 控制账本完整时，手动刷新只观察断点；继续清理需要新的明确确认及当前进度指纹。仅可继续此前登记条目。
- 未知文件、替换、权限或内容漂移、账本丢失或损坏均保留待核对。旧归档不支持恢复契约时拒绝，不套新控制器。
- 负载、控制文件、收尾三个阶段分别验证；回滚回执丢失时只读核对进程和全部清理记录的缺失，不重复删除。

- 云端控制传输只封装原事务已归档程序，保留原始字节和标准输入；压缩不能替换旧控制器、绕过归属校验或新建事务。命令超出有界长度时拒绝，不截断、不自动重试。

## 本端 DeepSeek 模型接线

- 仅本项目保存的“本端 DeepSeek”槽位能接入当前 Host；云端预备槽位不静默复用。
- 启用/停用均先预览，绑定计划和凭据版本，明确确认后才改变自有命名空间。不得改原生路由、默认模型或已有用户引用。
- 独立路由名为“DeepSeek（双端配置）”，复用官方公开传输服务，固定官方端点与 High；不允许普通输入改变发送 Key 的地址。
- 启用成功只代表本地接线，仍显示“尚未验证请求”；模型发现和简称解析不等于实际调用、审批或 worker 调度。
- 用当前 Host 的真实模型目录解析名字，唯一匹配后显示友好名称；歧义时自然语言说明候选，不要求输入 provider 技术标识。

### 工作台请求头边界

- 原生入口返回 HTTP 431 表示承载请求头过大，不等于云端掉线、机器人失效或任务失败。

- 不记录 Cookie 值，不自动清理浏览器登录信息或重放入口。仍超限时使用独立浏览器环境并手动重开，不改原生 DSH。

- 承载断开时分别读取本机进程退出记录与固定 SSH 诊断分类；分类来自进程输出，不证明故障根因。不得回显原始 stderr、主机凭据或私钥路径。
- 导览的 HTTP 鉴权、请求头、网关、响应契约错误与云端任务状态分开；本端请求失败不等于云端没执行。未知写操作只核对原回执，不重放。

- 结果未知先查原操作和版本，不重发。关闭未知操作只推进版本屏障、保留已有授权；不能冒充停用。无记录时形成停用屏障，阻断迟到的首次确认。
- 配对控制先阻止新增传输并排空已接收帧；未排空仍拒绝变更。先明确撤销配对再停受理，保留数据；挂载失败仍可撤销配对，不以已记账冒充已连接。
- Gitee 读取使用目标端独立槽位，凭据不经传输结果回传；模拟令牌测试不等于真实私有仓库验收。

- 第 6 页“本地与云端直连”只读取本地缓存；预览／确认／手动查询才访问云端。已确认的持久传输器独立处理队列，这不等于页面自动刷新。
- 本地确认结果未知不启动新接入器；撤销先停止本地再请求云端。查询离线保留先前明确的传输授权与队列，不假称云端已撤销；错误回执不启动 worker。
- 重启从自有凭据记录恢复原本地身份、命名空间及队列；不复制云端角色令牌，不改变原生模型、模式或用户 profile。旧静态部署保留原 HTTP 行为。
- 云端接收合同 2／3／4 均显示受理面板；仅合同 4 提供独立只读执行确认；配对只允许明确支持的合同，不用旧接口静默降级。切换已绑定目标前核对原传输授权，旧任务数据不发往新目标。

- 受管 SSH 帧按 FIFO 串行，最多 1 个在途加 2 个等待、单帧最长 30 秒；控制操作优先阻止新帧并等待原帧结束，其他控制请求明确报忙，不悄悄排队或重发。未知结果仍按原账本核对。

- 已配对云端重启时，admission 必须核对实际邮箱与合同 3 授权一致，不能把“有邮箱”误判为 worker 已开启；任一 worker／开发／交付执行器存在仍拒绝。旧归档的 admission 不原地替换，失败现场保留。

## 单次模型连通验收

- 保存、接入、名称解析不等于真实请求通过。连通验收须另预览并确认，只调用本项目独立路由；
  简称按目标清单唯一匹配，不借日常 Key、不自动换模型、保持 High，不改变默认模型。
- 单次最多 1 个请求、1024 输出 token、60 秒；固定测试文字、无工具，不启动任务或 worker。
  先记发送意图再调用官方 LLM 接口；状态查询与同一意图重放不再次调用模型。
- 回执只记结果和安全错误类别，不保存模型输出、思考或错误原文。未知结果不重试；
  再测须明确承认上次结果未知、可能已计费，重新预览与确认新意图。凭据变化使旧成功观察失效。
- 本端和受管云端均通过导览独立预览／确认，异步启动后手动查询；关闭页面不取消已确认请求。
- 云端仅原归档和当前 Host 均支持合同 2 才放行；启动回执未知先查，禁止重发或回退本端。
  请求在目标 Host 运行，不占住 SSH 控制命令；保留原时限，不拿模拟响应冒充真实上游验收。

### 模型名称有歧义时

- 先按实际目标端目录解析简称；不要求用户填写 provider 标识或点击 IM 卡片。
- 候选重名时可用普通接入名称补充，例如“请用 DeepSeek（双端配置）”或“我想用阿里云那个”。
  导览 resolve / probe preview 的可选 clarification 只用于目标端筛选；按钮也只是填入这段文字。
- 同名接入仍有歧义、否定／条件句／多选表述不能唯一筛选时继续澄清，不猜测、不调用模型。
  修改名称或补充说明后原预览失效；开始前重查目标目录与原精确策略。
- “已接入”是凭据绑定状态，是否请求成功看单独手动回执；无记录不说已验证。
  新补充说明须归档与真实 Host 都声明支持，旧版本明确拒绝，不静默丢弃字段。

## 规则与 Skill 维护

- `maintenance_status` / `maintenance_preview` 只读检查本 Host 已提交安装的所有权与当前字节；
  分别预览升级、同版本缺失修复、移除自有规则与 Skill。预览不执行。
- 合同 2 的 `maintenance_apply` 须明确确认同一预览 id／摘要，且基线未变、五分钟内；
  仅操作列出的规则与 Skill，不替代开发、commit、push 或发布授权。
- 用户在自有规则块之外追加或改写的文字逐字节保留；块内或 Skill 内容有改动则待核对。
  缺失原有用户规则文件不从旧备份偷偷重建；同名未知 Skill、链接不认领。
- 应用先存持久事务，再把原文件移入本 Host 私有备份，用拒绝覆盖方式发布；
  新出现的用户文件或并发改动保留并报告 needs_review，不强删、不覆盖。
- 丢失回复先按原 id 查询；重复原申请只返回原回执，不重做。中断后通过
  `maintenance_recoveryPreview` / `maintenance_recover` 明确确认回滚未完成改动；
  若已提交，只收尾原回执，不撤销成功的维护。未知或损坏账本停止核对。
- 只删除所有权证据匹配且为空的自有 Skill 目录；附加文件、备份和历史回执保留。
  预览和回执不返回原用户文字或凭据，不能把只读查询说成已应用。
- 原首次安装接口能识别维护后记录；卸载后可重新预览安装，不覆盖原用户规则。
- 本接口不升级插件二进制或卸载云端实例；凭据、任务、成果、原生配置和第三方插件保留。

维护确认界面：当前 Host 的第 5 页区分待确认计划、当前观察和持久回执。先手动核对，再分别预览升级、修复或移除；未知结果只查原回执，不再次提交。恢复计划需独立确认；仅收尾已提交事务不能描述成回滚。另一端需在其自身导览分别确认。浏览器查询引用不是批准，禁止以其恢复确认状态。

维护核对优先显示服务端当前待恢复事务，不能让浏览器记住的旧成功回执遮住它。恢复确认前列明原操作和涉及的受管文件；历史回执仅作历史证据，不代替当前状态。


## 智能体维护锁

- `agent_hold_status` 和 `agent_hold_preview` 只读观察当前 Host 的原生智能体；不查询用户输入正文。
- `agent_hold_apply` 仅在全部原生智能体空闲、明确确认当前预览后获得进程内维护锁。
  运行中拒绝，不取消任务；使用官方 `runMaintenance` 保留后续原生 inbox 输入，不复制、清空或重发。
- 锁生效后新建智能体的初始化完成等待释放，不嵌套官方初始化锁、不丢输入。外部取消或契约变化会降为待核对，不能冒称已安全排空。
- `agent_hold_release` 必须匹配当前进程实例与原操作，明确确认后释放；已有输入可恢复原生执行。
  锁不跨进程，重启后旧引用无效；状态刷新不能隐式重建锁或重放批准。
- 此能力仅覆盖原生智能体，不覆盖后台 job、子进程、文件传输或第三方插件工作。
  `hostStopAuthorized` 和 `pluginSwitchAuthorized` 均为 false，不能据此停止 Host 或切换插件版本。

## 自有网关维护锁

- `gateway_hold_status` / `gateway_hold_preview` 只读查看自有 Gateway 的在途请求、调度批次、
  文件传输、交付操作等；排队但未执行的任务不是当前执行。原任务所有权仍忙碌时不能宣称空闲。
- `gateway_hold_apply` 明确确认同一预览后，只有当当前工作均已结束才关闭新受理。
  忙碌时拒绝，不中止任务或清空队列；不得循环批准或强行停止来制造空闲。
- 生效后调度器、文件同步、A2A 端点及交付循环不领取新工作；已有队列保留。
  对端收到维护等待不消耗任务／文件发送的重试预算，不描述为版本错误或任务失败。
- 仅用当前进程与原操作执行 `gateway_hold_release`；释放可让原已授权队列继续，
  不新授予开发、提交、推送或发布权限；旧批准不重新获得锁。
- 此锁仅覆盖自有网关入口，不等于原生会话、导览后台进程、工作台代理流或第三方插件全部排空。
  不持久化、不触发 Host 停止或版本切换；禁止以测试控制器代替整机生命周期产品能力。


## 工作台连接与原生待处理输入

- 网关维护观察中的 `proxyHttp`、`proxyWebsocket` 计数来自实际连接生命周期，
  而不是打开工作台的 RPC 是否返回；两项包含在 `requests` 中，不要重复求和。
- 流式响应、WebSocket 握手与已连接会话尚未结束时，不得宣称可加网关维护锁。
  门禁拒绝不消费一次性工作台票据，不取消既有流，也不绕过原生 Cookie／Origin 校验。
- 浏览器关闭连接后按真实句柄释放计数；空闲 keepalive 套接字不算正在执行的工作。
- 原生智能体 `inboxState` 为 `pending` 或 `unknown` 时，不能以 `status: idle` 宣称无待处理输入。
  只观察公开收件箱的数量，不读取正文，不清除、迁移、重投或取消消息。
- 以上仍不是整机停止或版本切换许可；未挂接 Gateway 的新用户导览、后台初始化进程、
  第三方 IM 消费者以及跨重启维护账本，仍需完整生命周期验证。


## 停止安装进程不等于停止原生 Host

- 新停止流程先调用 `runtime_stop_preview`，由目标端返回签名计划、原进程身份及有效期。
  schema 1 只覆盖本事务安装进程，不使用旧 PID 直停路径；Host 风险停机必须另用 schema 2，见下文。
- `runtime_stop` 必须明确确认同一计划；本端先记请求，目标端先记停止意图，再发 SIGTERM。
  不删除文件、不发送 SIGKILL、不因回执丢失自动重发，也不把新进程当成旧进程停止。
- `runtime_stop_reconcile` 只核对原成员均已结束并持久记账，不补发信号。
  停止结果未核对前，不重新启动安装、复用新停止计划或删除原控制记录。
- 安装进程停止不代表 Host 已停止；schema 2 也不是无损排空或版本切换授权。

### 新用户导览的活动门禁

- `onboarding_hold_*` 管理本进程自有导览，不依赖 Gateway；不等于原生 Host 排空或持久维护批准。
- 活动含导览 RPC、启动配置、模型试调用及代理 HTTP／WebSocket；状态只显示固定类别计数，不含消息、密钥或模型输出。
- 模型超时／已请求取消不证明实际调用结束；原适配器尚未返回时继续占用活动，拒绝叠加试调用或宣称空闲。
- 加锁须单独预览、确认且实际无活动；不取消旧工作。释放绑定当前进程和原操作，不重放安装或模型。
- 无 Gateway 不代表无后台活动；本锁不管理第三方 IM、原生会话或远端独立安装，不能授权整机停机。


### 联合维护与依赖恢复

- `coordinated_hold_*` 将自有导览、已配置网关与公开原生智能体门禁作为同一操作获取和释放。
  缺必需组件、忙碌或依赖替换时拒绝原计划；已获取的部分只按原实例释放，不接管新依赖。
- 联合锁持有期间不得使用分项 RPC 单独释放；状态仍可查看。失败后按原操作核对，不另开计划覆盖。
- 原生待处理输入仍显示 pending／unknown；第三方 IM 显示未核验，不得描述为完整 Host 已排空。
- 维护期间新绑定的模型／本地配对初始化等待明确解锁；已销毁依赖不启动，新依赖不与旧初始化重叠。
  状态中的 settled 仅表示初始化回调结束，不证明模型凭据有效。失败不自动重试，刷新不触发启动。
- 当前联合操作仅在进程内生效，依赖漂移进入待核对；旧实例批准不得跨重启沿用。
  不包含持久维护账本、第三方 IM 排空、整机停机、版本切换或卸载授权。


### 持久维护回执

- `maintenance_record_preview/apply` 先保存自有维护意图，再获取联合组件锁；不会读取 Gitee 或模型密钥。
  `maintenance_record_releasePreview/releaseApply` 单独确认释放，先记释放意图，再调用原组件。
- `maintenance_record_status` 是只读观察，不写回执、不重试、不重建锁。
  意图写入或最终回执丢失时，重复获取确认只返回原记录，不补发组件操作。
- `maintenance_record_recoveryPreview/recover` 仅核对本实例现有组件状态，明确确认后补记观察结果。
  核对不调用获取或释放；释放未完成仍需单独预览、确认，不能由“核对”偷偷恢复执行。
- 旧实例的未结束记录显示 interrupted，并说明普通执行可能已经恢复；旧批准不会跨重启续锁。
  当前不能证明旧实例已终止时，不清理旧记录、不覆盖所有者，整机停机和升级仍关闭。
- 未结束账本阻止绕过记录层调用原联合／分项变更；依赖或账本身份变化时保留待核对。
  仅保存固定元数据，不保存消息正文、模型输出或令牌。最多保留 128 个操作，满额需核对，不自动删历史。
- 本回执是持久记录，不是持久的整机准入屏障；原生 Host 和第三方 IM 的完整生命周期仍待核验。


### 旧维护实例的受控收尾

- 维护记录合同 2 保存进程出生身份及单向散列后的主机标识，不保存原始机器序列号，不建立账号权限隔离。
- `maintenance_record_retirementPreview` 只观察旧所有者是否已经退出；主机／命名空间不匹配、仍存活、
  身份缺失或读取失败时不可应用。PID 不同或进程名相同都不是充分证据。
- `maintenance_record_retirementApply` 必须确认同一计划，并重新核对原记录、修订号和退出证据。
  它只将旧记录标为 retired，保留历史；不发进程信号、不删除配置、不获取或释放组件锁。
- 收尾后如需新维护，必须重新预览和确认。收尾本身不授权执行、开发、停机、升级或发布。
- schema 1 的旧记录没有进程身份时保留待核对，不从旧 PID 或文本推断，不擅自补造证明。
  旧已完成记录可在合法追加时保护性转换结构，原操作内容保留。
- Linux、macOS、Windows 分别读取本机进程元数据；平台或系统接口不可用时返回未知，不按“已退出”处理。
  Windows 真实系统验收未完成时，不把模拟适配测试宣称为 Windows 真机通过。
- macOS 使用公开 libproc 的微秒出生时间，不启动提权的 ps、不放宽沙箱或复制系统程序。
  老的秒级时间记录与新格式不同不能判成 PID 复用；权限不足或结构不符保留未知。

### 维护会话界面

- 第 5 页的“维护会话与记录”使用当前 Host 的真实账本，和规则／Skill 文件维护分开。
  只在协商到记录合同 2 与查询合同 1 后开放；不向旧端降级发送变更。
- 打开页面不读账本或自动执行，手动核对才更新观察。每次动作先预览，再单独确认；刷新取消旧计划。
- 当前观察和历史查询回执分开显示，旧成功回执不遮蔽新未结束记录。
  浏览器只保存原操作的查询引用，不保存批准；结果未知只能手动核对，不自动重发。
- 显式释放可能使普通工作继续；观察核对和旧实例收尾只记账，不隐式释放。
  第三方 IM 未完成排空时始终提示边界，按钮不能授权整机停机、升级、卸载、开发或发布。

维护会话从导览顶栏独立打开；草稿加载失败或组件持锁时仍可进入。打开不查询，关闭不释放；重新打开后手动核对，旧确认不恢复。


### 模型服务重载与维护所有权

- 配置／维护入口独立于模型执行依赖；原生模型服务重载不代表用户同意释放组件锁。
- 持锁期间的新模型绑定延后注册，销毁的旧绑定不恢复；仅显式释放后启动当前依赖一次。
- 读取状态不请求模型、不修改默认模型或绑定批准。模型服务暂不可用时如实显示能力缺失。
- 执行网关有独立依赖作用域；网关或智能体替换后须重核对组件，不继承原组件批准。
  本行为不是整机持久维护或自动停机、升级许可。


### 持锁网关换代后的结束核对

- 当前网关与原维护捕获的网关分别观察；服务消失或 closed 标记不证明原实例排空。
- 仅原实例在原请求结束、所有活动为零、监听停止及数据库关闭成功后，才提供固定身份的关闭证明。
  失败、活动残留或存储关闭异常保留待核对，不通过刷新补造证明。
- 用户重新预览并确认释放后，可凭原证明结束旧网关这一项，再释放其他原组件；不调用新网关的解锁。
  释放预览绑定原组件证据，证据变化须新预览，不自动重试。
- 本证明不授权 Host 停机、升级或卸载，也不是原任务或消息成功凭证；原维护历史保留。


### 维护后的启动准入

- 启动先读原维护账本；等待、不可读或未结束时，不启动自有网关、模型接入、云端运行时或本地配对。
- 旧记录收尾、只读查询和补记回执不等于恢复。使用 `maintenance_record_resumePreview` 预览，
  用户确认后才调用 `maintenance_record_resumeApply`；确认只恢复当前有效启动，不重发未知消息或失败请求。
- 凭据提供方变更、丢失回执或过期计划先手动核对；不得绕过账本开放入口、重建编号或清除历史。
- 该屏障仅覆盖自有执行启动，原生会话和第三方 IM 仍需单独核验，不授权停机、升级或卸载。
- IM 维护允许提供显式有损断开选项：先说明在途发送和待决交互可能中止，再由用户确认；默认不自动操作，
  保留配置，恢复另行确认，不自动重发被中止的消息。候选已接入公开管理 RPC；操作界面与真实机器人回归仍待完成。

### 显式有损 IM 维护

- 仅 `im_maintenance_preview/apply` 可执行已选机器人的有损断开；须确认在途发送和待决交互可能中止。默认不操作。
- 先保存意图，再调用公开 `bot.disconnect`；禁用删除凭据的旧 `connection.disconnect`，不读写第三方配置。
- 恢复另预览确认，仅 `bot.reconnect`，不附带测试消息；原错误与未知回执不自动重发。
- 未知结果使用 `im_maintenance_reconcilePreview/reconcileApply` 只记当前观察，不证明原发送或断开已完成。原实例仍可能在途时不收尾。
- 官方飞书重启 Host 会自动重连：当前断开只在本进程有效，不能当持久停机证明或升级、卸载授权。其他渠道不假定具备飞书的断开契约。

- 在导览的“维护会话”进入 IM 连接维护，先手动核对，再按机器人名称选择；当前只管理所在 Host，不代替另一端的确认。
- 连接清单不可用时仍可读原账本，但不能把空清单当成空闲；不得变更连接。
- 浏览器只保留查询引用，关闭或重开不沿用批准。未知操作查询原编号，未知核对还须匹配原核对决定；不能用另一条回执或当前离线状态替代。
- 原账本只读兼容旧格式；显式操作才写新格式，不因打开界面自动迁移或删除历史。全局规则原文和日常配置不变。


### 已有 Host 的重启影响确认

- 首次空配置安装与已有 Host 重启不同。重启保留现有配置，原生工作或 IM 连接可能恢复，不能沿用“无模型／未启用 IM”的初始化说明。
- 只有归档声明 `onboardingHostRestartConsent: 1` 且计划包含完整 `resumePolicy` 才可发起新重启。用户确认可能恢复原生工作与 IM 后，传递 `acknowledgeNativeResume: true`；不是任务开发、提交或推送授权。
- 该确认贯穿本端意图、目标控制器、重启 worker 与原生启动器；未确认不得写重启意图或导入原生 CLI。旧归档仍可查询原记录，不能替换控制器绕过契约。
- 重启不等于无损暂停，不会清除维护账本；自有执行仍独立核对准入。未知重启保持原引用，不自动重放。


### 原生验收探针范围

- 启动检查只限制本次 nonce 对应的四个验收会话，使用公开 `agent/request` 事件；不得注册 Host 全局拒绝型 `llm/stream` 钩子。
- `modelAttempts` 仅计验收会话，并以 `modelAttemptScope: inspection_agents_only` 标注；不能据此声明其他原生会话没有调用模型。
- 检查结束卸载本次监听。正常会话请求保持原参数、结果与错误，不重路由、不重试、不读取日常凭据。


### 插件本体离线修复（运行时候选，未正式部署）

### Host 风险停机（候选接线，未正式部署）

- schema 1 仍只停止安装进程；schema 2 只覆盖原事务独立 Host，不包括 ECS 或其他服务。
- 先预览签名计划和风险；明确确认原生新输入及在途 IM 可能中止，再传 `acknowledgeNativeInterruption: true`。
- 未知忙闲、待处理输入、活动工作、实例变化或旧归档缺契约均拒绝；不换控制器绕过。
- 自有持久队列保留，不是无损排空；不自动停止、强杀、补发信号或恢复启动。
- 本端先记请求、目标先记意图再发一次 SIGTERM；另行核对原计划进程全部退出。
- 单元／模拟回归不等于真实 DSH Host 停机验收；完整版本事务仍未完成。

- 停机计划最多 5 分钟，状态观察 60 秒，先到期者失效。保留过期确认与原因，须手动刷新、重新预览和确认；不自动续用或削弱门禁。

### 跨版本事务（候选 RPC 与导览维护入口）

- 同版本修复不授权升级。新安装原归档必须明确支持跨版本；不能替换旧控制器或重建归属接管旧实例。
- 离线事务绑定原安装、运行时、新旧清单和签名计划；只切换自有 plugin 目录，保留原目录及文件身份供回滚。
- 未核验停机／归属、过期、内容漂移、未知文件或不支持独占重命名时拒绝，不降级为覆盖式移动。
- 中断先查同一事务，再单独确认恢复；已提交版本的回滚需要新计划和确认。原规则、Skill 安装、配置、凭据、任务数据不随二进制目录切换而改写。
- 新原归档须有 `onboardingPluginVersion: 1` 和 `onboardingPluginVersionRequests: 1`。操作者的 `cloud_version` RPC 已接入本端持久账本；不是模型工具，不接收任意 URL、路径或上传字节，候选只来自本端自有分发包。旧归档缺能力须拒绝，不能用新控制器接管。
- 接收候选要求独立 ID、明确确认、完整清单及固定 Host／依赖兼容性；不下载、解包或安装依赖。失败或丢回执先查同一 ID，不重发；接收成功不改变运行中的插件。
- 签名版本链只替换自有插件归属，原 inventory 不重写；未完成事务阻止修复／重启。版本记录与备份保留时不允许普通清理绕过；三制品未协调时不启动新版本。
- 本端预览会保存候选快照，不联系 ECS；接收、版本切换、恢复、回滚分别预览并确认，发 SSH 前先持久记意图。重开仅显示历史，不自动发请求；丢回执手动查原候选／事务，未找到记录不等于未执行，旧的已切换状态不能结清未知回滚。
- 已核对为失败的部分接收保留文件但不能用于切换；未终态的文件版本事务继续阻止新维护。拒绝一个恢复请求不能抹掉此前未完成的事务。
- 仅目标端明确返回“进入版本操作前已拒绝”的回执，才可结清该请求；例如 Host 未停或原运行时预检失败。普通错误、查询不到记录或 SSH 超时不等于没有执行，不能自动重试。

- 配套更新须单独预览确认，先写签名意图。中断核对原事务；恢复另作新计划，不重放应用。候选镜像切回旧版不会顺便覆盖规则，须再次确认将规则与当前镜像配套，期间不能启动。
- 三制品内容匹配仅解除文件配套门禁，不授权重启，也不证明运行中加载。未知配套事务阻止版本移动与普通清理；真实新 Host 跨版本加载仍待验收，不以文件事务代替。

- 第 6 页「自有插件版本维护」分开接收候选、切换文件、配套规则与 Skill。按版本／次数选择，不要求用户输入事务编号。展开只读本端记录；远端查询、预览及每次执行均手动触发，重开不续用批准。
- `rules_record` 仅本端历史；`rules_preview`／`rules_apply` 单独配套；`rules_status` 查原单；`rules_recover_preview`／`rules_recover` 新预览并确认恢复。原归档缺配套契约不扩权。请求先落本端意图，未知结果阻止新版本／规则维护、修复和重启；缺记录不当未执行。

- 新进程准入核对从实际加载模块导出的插件版本；文件包标签不够。原生 receipt 的 pluginVersion 为该次启动记录；describe 的 pluginVersion 来自当前已加载模块。版本字段不代替四种原生工作模式、全局规则及 Skill 的加载检查。

### 版本历史感知修复

- 原归档与候选均有 `onboardingVersionRepair: 1` 时，离线修复跟随签名有效版本；只用该版本保留归档，不能退回首次安装版本或从任意地址取文件。
- 修复单独预览确认，保存损坏内容备份与已发布身份增量；不改原归属清单。未知文件、同字节换 inode、目录漂移、在运行的 Host 或未核对事务均拒绝。
- 丢回执先查原修复；恢复只核对原日志，不重发。升级后修复仍可单独回滚版本；回滚后修复跟随回滚版本。缺归档或日志时保留待核对，不重建归属。
- 文件修复不等于在线生效。原归档支持 `onboardingVersionRepairActivation: 1` 时，可在修复后独立确认重启，再手动核验当前进程、实际加载版本、签名镜像及全局规则／Skill 配套；历史回执只作历史，不自动启动任务。缺契约或已切换版本时不能沿用旧生效回执。
- 历史感知卸载的离线控制器见下节；普通清理仍不可绕过版本历史，不删除版本或修复备份扩权。

- 生效核验是附加的只读能力。旧归档可接收兼容的新插件文件，但不因此获得新的核验权限；界面按原归档能力提示。
  原归档已经依赖的契约不可删除或改为未知版本。文件可升级不等于控制器可升级，禁止改写旧归档补能力。
- `RUNTIME_VERSION_IMAGE_DRIFT` 表示当前插件文件与签名版本不符，须保留现场并预览同版本修复；
  不重试启动、不把报错当作未执行证明，也不扩大归属或删除范围。未知异常仍只显示通用代码，不回显私密异常原文。

### 三制品卸载（离线控制器与导览候选）

- 原归档须声明 `onboardingPluginUninstall: 1` 及版本生命周期/规则配套契约；不能给旧归档补能力或换控制器接管。
- `uninstall_preview` 核验原 Host 已停、独占锁、签名当前镜像及规则/Skill 归属；预览不移除文件。另确认 `uninstall_apply` 才写意图并执行。
- 仅移除未被用户修改的自有托管块和 Skill；插件目录以禁止覆盖的原子重命名移入自有保留区。用户原文、旁置文件、配置/凭据、会话/成果、依赖、版本/修复历史和备份保留；不是删除整个 Host、ECS 或本地控制器。
- `uninstall_status` 是历史查询，不重放、不证明在线状态。丢回执查原单；`uninstall_recoveryPreview` 后须重新确认 `uninstall_recover`。内层日志不完整、未知文件或身份漂移保持待核对，不删锁重建归属。
- 内层日志缺失不能当未执行。仅原外层意图、内层锁/事务目录均不存在、镜像/元数据及操作前文件身份完全相符，才允许另确认取消尚未开始的卸载；取消不重放、不改目标文件。下一次尝试重新预览确认。
- 未完成和已完成的卸载均阻止原受管 Host 重启、版本移动及普通清理；完整回滚才解除。已退役插件及卸载账本不删除；运行时文件回收须独立能力、预览和确认，见下文。
- 原归档另有 `onboardingPluginUninstallRequests: 1` 才可经 `cloud_version` 的 uninstall_* 操作者 RPC 使用本端持久请求。意图先于 SSH，回执严格绑定原安装/运行时/计划；未知先查同一记录，找不到不当未执行，拒绝恢复不抹去旧待核对。
- 第 6 页「保护性卸载自有能力」按版本/次数选择，无需手输 ID。打开只读本端历史；手动预览范围、核对保留项并勾选确认。确认过期、关闭、停机观察失效均不续用批准；恢复另确认，完成卸载后仍阻止重启。
- 同步请求超时不代表目标端停止；首次查询若仍忙碌，保留原请求，待原执行状态变化再手动核对，不能重新应用或强删锁。性能优化不能跳过全量校验、提高等待限额或刷新归属。
- 本地自卸载及整机回收须独立验收；文件控制器、模拟界面或测试进程 SIGKILL 不能冒称 DSH 原生崩溃恢复。

### 本端插件来源预检（只读）

- `self_maintenance_status` 仅经官方 pluginManager 的公开清单，识别当前加载入口及唯一包关系；不接受用户输入的包名、路径或入口 ID。不扫描目录认领归属，不返回安装源或私密配置。

- `profile_bundle_observed` 只说明官方清单列出了可移除包，不是停机、卸载或热更新授权；实际停用/移包/停机须使用下述独立确认流程。自卸载会使自己的回执入口消失，不能用云端目录退役逻辑替代官方包管理器。
- 本端规则/Skill、官方包维护、独立 Host 回收分开。停机需新鲜忙闲/身份检查和显式风险确认，最后到达的原生输入可能中止；默认不停止、不自动重试、不清空用户数据。

- 官方包管理器可能以硬链接或只读目录保存包模板；只读来源读取允许这些形式，并校验路径、文件描述符及读取期间变化。不因此认领 pnpm store，不改源码文件或缓存权限。目标 AGENTS.md、Skill、账本和恢复文件仍要求原有单链接及归属校验，不能放宽写入门禁。


## 官方本端停用与外部恢复

- `self_disable_*` 仅取消本插件包的加载选择，不卸载包、规则或 Skill，也不停止或重启 Host。
- 先取得本实例的持久组件维护会话，再独立预览、确认停用风险；组件锁不是全局输入屏障。
- 本插件界面和 RPC 可能消失；官方返回待重启时只说明配置已保存，不说当前已停用。
- 操作前记意图，未知回执只查询不重发；恢复入口是原生插件管理器，不能让已停用插件自行承诺恢复。
- 未决旧操作须核验原进程已退出后另确认补记当前观察；不追认旧请求成功，不重放管理器操作。
- 重新启用本包及 Host 重启均须另行确认；维护准入继续关闭，按原会话恢复流程处理。

- 本端停用使用维护会话中的独立确认区；先保存恢复说明。界面消失不等于成功，恢复由官方插件管理重新启用；再手动核对原账本，任务入口另行确认恢复。不得把旧查询引用当授权。

## 本端包移除（候选确认界面）

- `self_remove_*` 仅通过官方 `pluginManager.removeBundle` 移除本项目固定包；先取得持久维护并单独确认风险，不借用停用批准。
- 保留全局规则、Skill、凭据、任务、会话、成果和备份；这不是 Host 停机或实例整体卸载。官方包管理可能修剪未使用的 profile 依赖。
- 意图先落账，HMR 自卸载可能丢回执；未知结果禁止重发，也阻止换用停用接口绕过。
- 恢复需保留的已验证包源，通过官方插件管理重新安装；当前私有包未发布，不能声称按包名即可从市场下载。原进程退出后才可另确认补记当前观察，不能追认原操作成功。

- 在独立维护窗口选择“停用插件”或“移除插件包”；切换不执行、不复用另一动作批准。移除前保存恢复说明并确认保留已验证包源；未发布私有包不能假定市场可重装。
- 打开和切换不自动查询，回执仅手动核对。浏览器只保存本动作诊断引用；缺失历史记录保持未知，其他动作不能绕过。

## 本端 Host 停机（独立确认界面）

- `self_stop_*` 只请求当前 Host 官方 `appExit(0)`，不直接发信号、修改 DSH、停止另一端或选择任意 PID。没有公开退出能力时拒绝执行，保留人工停机。
- 先保存草稿、取得持久组件维护并核验空闲，再独立确认有损停机风险。最后时刻到达的原生/IM 输入可能中止；外部守护程序可能自动重启，不宣称全局输入已冻结。
- 停机意图先持久落账；退出请求返回或连接丢失不是退出证明，未知不重发，也禁止换停用/移包或释放维护绕过。保留规则、Skill、凭据、会话、队列、成果与备份，不清理数据。
- 重新启动后手动查询原记录，核验原进程确已退出，再单独确认仅补记当前观察；不追认退出一定由原请求导致，不自动重启。旧维护记录收尾、自有受理恢复分别确认。原生输入/第三方 IM 的重启行为不由自有队列屏障控制。

- 在维护会话选择“停止本端 Host”，不与停用或移包共用批准；先保存停机恢复说明、草稿，再确认有损风险。缺退出能力时保留只读查询/核对，不提供强杀按钮。
- 停机与补记退出观察使用独立确认；只保存诊断引用，打开/切换/重开不自动请求。旧维护收尾和恢复受理仍在组件维护区分别确认。

## 独立 Host 的离线运行时回收

- 原归档声明 `onboardingRuntimeReclamation: 1` 才可调用；新版本镜像不补授旧控制器权限。
  不改写旧清单，不因当前目录看似属于插件就收编新文件。
- 先确认原 Host、安装子进程与重启启动器均已退出，三制品卸载已完成且退役镜像完整。
  `reclaim_preview` 仅按原始签名清单列出依赖/运行时文件、数量和保留目录，预览不删除。
- `reclaim_apply` 必须另行明确确认不可逆清理；五分钟预览过期须重做。
  保留 native-home、native-tmp、workspace、原安装源、控制账本、退役插件及所有备份。
  用户规则、凭据、会话和成果不重新扫描认领；保留目录被替换或未知文件出现则拒绝。
- 删除前写持久意图，分批记账；丢回执不自动重发。`reclaim_status` 是历史查询，不证明实时状态。
  `reclaim_recoveryPreview` 后单独确认 `reclaim_recover`，只能继续原清单；漂移保留待核对。
  已执行的删除不承诺回滚。恢复不会重新安装、启动 Host、清理用户数据或删除控制记录。
- 清理未完成和已完成都阻止受管重启/版本切换；缺失或损坏账本不能视作从未操作。
  不删除整个实例目录、ECS 实例或外部服务，不宣称同账号其他进程已被隔离。
- 原归档另有 `onboardingRuntimeReclamationRequests: 1` 才开放 `cloud_version` 的 reclaim_* 持久请求。
  本端意图先于 SSH；请求结果未知只能查原单，重新打开只读本端账本，不自动查询目标或重复删除。
- 若查询暂未观察到目标意图，仍保留结果未知。另行预览/确认恢复后，在目标独占锁内再次核验原清单；
  仍无意图才登记执行，若迟到原请求已经先执行则拒绝过期恢复。不能以记录缺失证明从未执行。
- 仅目标端明确返回执行前的 `PLAN_EXPIRED`，才记本次确认已失效；旧确认仍不重发。
  内容漂移、账本缺失、其他请求或传输错误不能归类为未执行，继续保留待核对。
- 第 6 页“独立运行时精确回收”与三制品卸载分开；先核对卸载已完成及最近停机观察，
  查看清理/保留范围，再勾选不可逆风险。关闭、取消、过期均不沿用批准；恢复另确认。
- 本端持久请求和界面已接线；真实原生 Host 回收、实际依赖规模性能仍须独立验收。
  模拟目录、模拟 RPC 界面或独立 Node 控制器恢复，不等于实际双端 Host 全流程已通过。


### 原归档后台回收

- 原归档另声明 `onboardingRuntimeReclamationWorker: 1` 才使用受管后台执行；新镜像不能补授旧归档。
- 本端请求、目标删除意图、worker 出生身份依次持久化。释放目标独占锁后才交付启动输入；
  身份未落账或父进程提前退出时，不授权删除。已绑定的 worker 账本缺失/损坏必须待核对。
- `executionState: running` 只表示本次观察到原 worker 活动，不表示删除完成；已记账条目不是实时百分比。
  `reclaim_status` 只读，不取得长时间写锁、不继续删除；手动刷新，不轮询、不提高传输超时。
- 活动 worker 禁止重复启动/恢复；进程身份未知不能判已结束。确认中断后，恢复须新预览及单独批准，
  绑定原删除清单与新执行代次；迟到旧 worker 或旧恢复确认不能执行。完成后继续阻止受管重启。
- 本候选的受管后台代码仍需真实官方 Host 的同规模回收、活动查询及受控中断恢复验收；
  alpha48 的原请求超时后自行继续，不等于已经验证本版受管 worker。

## 卸载后的手动观察

- 权威运行时卸载／回收已开始（含待核对）且原进程均停止时，保留历史修复回执，不向不可修复目标查询修复状态。
- 历史修复成功不等于仍安装或在线；卸载后禁止修复、重启。手动刷新只观察，不授权回收；回收仍需独立预览确认。
- 状态矛盾、请求未知或进程活动仍须待核对，不能吞掉一般修复错误、清除待决记录或重建归属。

- 回收中断不恢复修复能力；手动读取原回收检查点，继续删除须新预览和独立确认。活动回收 worker 不能再次启动。

## 普通版本加载核验

- 文件切换、规则与 Skill 配套、风险确认后重启、手动加载核验分别进行。正常升级不要求先制造文件损坏或修复事务。
- `cloud_version.activation_verify` 只观察当前原生进程与签名版本、全局规则及 Skill 配套；不重启、不开放任务写入、不修改文件维护回执。
- 原安装归档必须支持 `onboardingVersionActivation: 1`。安装新镜像不会补授旧归档能力，不改原控制器或所有权清单。
- 记录绑定版本事务及镜像、重启与进程出生身份。只有该次手动核验可报告“该时刻已加载”；本端记录与远端历史查询均不是实时在线证明。
- 未完成文件/规则维护、未知重启、待修复或已卸载/回收时不核验成功；保留历史，不通过改账本、伪造修复或自动重发绕过。

## 只读后台任务的显式启用（运行时合同 4）

- 受理和只读执行分开授权。旧受理授权迁移后仍关闭 worker；先预览“启用只读执行”，明确模型费用、重启恢复和原只读队列继续的范围，再确认。不得把下一页、配对或模型 Key 保存视为执行许可。
- 每个任务的模型按目标端实际配置和用户自然语言选择；云端默认 high，不固定为某个模型。未指定或有歧义时先询问。独立 worker 不占用入口会话；授权状态与调度器实际挂载分别核对。
- 只允许现有只读工具与插件私有成果区，不开放 shell、任意文件、开发、commit、push 或发布。停用时必须排空自有在途工作；队列、检查点、成果保留，重启只恢复已授予的能力。变更配对前先停用只读执行。
- 保存结果未知先查原操作，不重复确认；旧签名控制器不支持合同 4 时明确停止，不能改写旧归档、伪造合同 3 或绕过目标验证。兼容配置、模型探针、真实业务与真实 IM 验收分开记账。

## 第 3 页默认收发机器人

已有双端直连时，经当前配对协议读取云端公开 IM 目标，不要求重新初始化 ECS 或伪造安装归档。
预览和确认绑定原云端实例；对端重启、替换或缺能力须重新核对，不改读本地机器人或其他云端。

可跳过，不强制 IM。用户可选择本地或云端机器人作为默认交办入口与结果返回端；两端的原生 IM 仍保留，不接管或关闭另一端。发送机器人不等于收件对话：从选定端的公开服务读取已保存目标，唯一候选可预选，但必须预览确认；多项不猜测，不填内部 ID。首次无目标时引导用户与该机器人私聊并在原生 IM 中保存目标，不自动建立群或读取私有配置。

确认保存后，配对未完成只能报告“待同步”。云端记账后，仅新建的云端定时任务继承；本地端离线时本地通知排队，选云端则不依赖 Mac。前端只手动刷新；后台既有通知引擎可恢复已确认的策略同步。跳过导览不撤销已有授权；停用默认通知须单独确认。不重试历史任务、不回填历史结果，不授予开发、commit、push 或发布。

## 既有双端只读核验（候选）

- `existing_pair_inspect` 只读核对已配对 Host。只用当前认证直连及新增能力协商；缺能力、断线、角色／实例改变时停止，不沿用旧缓存、不另建 Host 代替。
- 当前仅显示模型清单、IM 配置数量、实际进程路径、规则文件状态与运行时开关。清单不证明模型调用、IM 连通或仓库访问；规则文件核验不证明会话已加载。
- 不复制凭据、不改配置、不建立安装归属、不接管原生 Host 生命周期。结果不是安装、重装或全链路验收回执；不能因此跳过后续显式配置和真实任务验收。

## 既有配置的六页复用确认（候选）

- 已有认证直连时，从“复用已有双端”逐页核对；不拿新建 ECS 的安装流程接管旧 Host，也不重复索取或复制模型、IM、Gitee 凭据。新用户仍走原新环境流程。
- 第 2 页以云端实际清单解析用户模型简称，有歧义用普通文字补充渠道；默认 high。解析不调用模型、不设 worker 固定模型，也不改变本地原生默认。
- 第 3、4 页分别可选核对现有默认收发入口、Gitee 任务成果仓库。IM 要同时核对云端权威默认账本；仓库通过目标端 API 只读核验，不克隆、不创建任务绑定。跳过保留原设置。

- 保存未知先查询原操作回执，不重复确认；需要关闭待决时显式确认版本屏障，不清除实际配置。历史回执不代表持续在线或全链路验收；真实任务、IM 与成果另验。
