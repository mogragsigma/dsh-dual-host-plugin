# 云端 Web 工作台

- 本地 Desktop 的「双端工作台 → 云端工作区」入口可打开真实云端 Web，并按任务名称查看执行会话。
  页面通过 DSH 原生浏览器容器承载；Web profile 默认可能未启用官方 browser 面板。
  若缺少容器，明确提示并保留失败信息；仅在获准的自有安装覆盖层按公开配置显式启用，不改 DSH/第三方源码，不擅改正式配置。
  切换失败不代表任务执行失败，不重新启动任务；不要将短时登录入口或 Cookie 当成成果链接。
- 打开页面、刷新状态、查看会话不启动 worker，不重复受理任务，也不重试历史 pending／needs_review。
- 请求模型只是任务策略；实际调用模型与完整结果在真实会话记录核验。没有调用证据时不能声称已经使用模型。
- 断线时先用 task_diagnostics 核对应用协议与状态新鲜度，再请用户点击工作台重新打开。
  不把 SSH 进程存在、页面 load 或历史快照说成已登录、已完成或对端空闲。
- Web 登录随 Host 重启可能变化，插件通过公开 Host 接口获取当代登录入口。
  不读取或展示日志 token，不把凭据、临时入口链接、Cookie 贴进模型上下文、IM、文档或任务状态。
- 只有用户界面的已认证请求才能创建短时入口。模型不冒充已经打开窗口，不自行使用 bash 读取配置凭据。
- 受管开发默认关闭，实际能力以配置、审批与当前门禁共同决定；提交、推送和发布仍关闭。完整 Web 保留原生权限，不是整个云端 root 环境的只读隔离。
  原生 Shell、设置或终端操作仍须明确授权，不用工作台绕过审批。
- 本机离线时用户直接访问云端 IM／已有云端 Web；本地隧道不是云端任务调度的必需条件。

- 「刷新状态」仅手动更新快照；切换已加载的视图不自动重查。已过期的会话条目先刷新再导航；「打开云端 Web」始终通过现有 Host 接口重新获取短时入口，不用缓存 token。
- 工作区的「任务与成果」进入对应任务详情，不伪造文件下载；已登记成果介绍和安全跳转按 task-artifacts：Gitee 外部页面或非仓库成果的所属执行会话，不自动上传。

- 首次配置从同一「双端工作台」进入六页导览；已配置用户点击「配置导览」，未配置网关时优先展示导览。先加载 task-onboarding。本期仅本端只读检测和格式校验，不初始化或写入；不要用旧部署脚本填补未实现能力。

## 新导览安装的成果入口

执行会话入口复用导览已验证的云端承载，不要求用户再填写旧端口。仅打开当前配对账本所属的执行会话；目标、实例或原生令牌不一致即拒绝。不要把登录令牌或 localhost 链接发到 IM；IM 中说明从本地“双端工作台”按任务名称进入成果。
