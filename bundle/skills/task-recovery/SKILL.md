# 当前恢复边界

- 自有持久受理点是 task_submit 保存；它之前的普通 IM 收件由原生 IM 插件负责，不声称已由本插件可靠入箱。
- task_submit queued_locally 是本地待送达，accepted 是云端已登记；两者都不证明 worker 正在执行。
- peer 的 queued、broker_saved、peer_saved 分别表示本端排队、云端 broker 保存、对端 inbox 保存；不是模型阅读、执行或审批。
- 目标 inbox 先保存再 ACK，重放须按来源和内容指纹去重；冲突或 needs_review 不自行删队列重试。
- IM 通知通过公开 sendChecked 契约。sent 与平台消息 ID 证明平台接受，不保证用户已阅读。
- 发送结果未知须人工核对，不能盲目重发。没有兼容的可选 IM 服务时，通知保留队列，任务状态不丢失。
- 旧 durable inbox 的 processing/done 属于历史链路，保留记录，不自动启动旧消费者、重放脚本或补丁。
- SSH 重连、消息确认或租约到期均不转移任务 owner/epoch；断线不是空闲，恢复不构成人类开发批准。
- 不承诺远端 exactly-once，不假装补拉所有离线期间未收到的 IM 消息。

## 统一诊断入口

连接、版本、状态新鲜度、队列恢复或回执语义不明确时加载 task-diagnostics，使用 task_diagnostics 只读查询。
缓存不代表当前状态，方案投递 sent 不等于批准回执；不要自动重发、解锁或重启。


## 持久调度恢复

- triggers:1 是独立协商能力，缺失时保持原计划，不改为单次任务绕过。
- 触发先保存 occurrence 意图，再幂等建立批次；重启恢复相同 occurrence/job，不增加预算。
- 等输入、时间、依赖或事件时无模型空转；多次错过时段合并，skipped 如实展示。
- 旧 Host 不认识新批次版本时保持待核对；升级回来也不能把 needs_review 自动改为 queued。
- 暂停不是排空。相同任务旧 agent 尚未退出前，新任务批次不能借并发槽重新开始。

## 子任务图恢复

- 先查 task_workflow_list。父图、节点意图、job 和 run 不同；节点 prepared 只表示持久意图，尚非执行。
- 新子任务记录版本为 0.17.1；旧消费者不认识时必须待核对，不能降级字段、清库或恢复为旧版可执行记录。
- 整图共享次数包含已中断批次；恢复不会重建新预算。节点失败、待审批或整图待核对不能当成依赖成功。
- 暂停控制未完成时，后续恢复不能超车；只由同一个控制器恢复自己的暂停，并等待真实 worker 排空。


## 调度库首次 owner 迁移

遇到 SCHEDULER_OWNER_MIGRATION_REQUIRED，不换端口或删库。由运营方从历史有效配置核对旧端口，
确认旧 Host 已停止，使用自有 scheduler-migration 内部接口生成绑定数据库身份和行摘要的计划。
占用旧端口时迁移拒绝；计划过时或库被替换须重新核验。先生成独立备份，再只记录 owner。
迁移本身不会恢复 job，启动后未知开发操作仍待核对；旧端 rollback 必须先停止新端并沿用原端口。


### 推送监管终态核对

推送前由插件把监管回执绑定到操作、动作、代际、意向／计划摘要、随机nonce、启动标识及私有目录身份，随后才启动监管进程。
主进程崩溃丢失stdout时，不凭PID不存在补记排空；仅由运营使用私有核对接口检查完整、未替换的封存终态，且原监管进程已不再执行。
核对只关闭对应子进程操作，不释放任务，不授权重试，也不证明远端已接收。随后必须独立核验工作区、仓库身份和远端引用才能结案。
缺失、损坏、外来、目录被替换或仍存活的监管证据保持待核对；不会在启动、定时器或模型工具里自动采用。
终态文件不含stdout／stderr、环境、Git参数或密钥路径；这不是签名或操作系统身份隔离，不能对抗可同时改写数据库及私有目录的管理员。
