# 双端安全交接

- 当前任务忙碌时只能登记修改意图；其他任务忙碌不构成本任务的锁。
- 只有受控写入器可验证 owner、epoch、基线哈希后修改绑定仓库。
- 所有者离线不允许按超时自动夺权。存在 granted、writing 或不确定副作用时不得报告空闲。
- 仓库绑定由部署配置提供，模型不能选择任意绝对路径、分支或凭据。
- 本版本入口没有写入或发布工具。不要以 shell、其他插件、子智能体或直接 Gitee API 绕过。
- 本地 Git 提交不等于已推送 Gitee；发布需独立用户批准和发布器验收。
- A2A 状态摘要不是人类批准或所有权凭据，不能据此开始开发或写入。

- 收件箱 claim 租约只管理消息投递，不是任务写锁；消息恢复、SSH 重连或回执成功都不转移 owner/epoch。
- 本轮按用户要求不做操作系统身份隔离；不能将插件内门禁描述为宿主级权限隔离。

- worker 规划状态与仓库修改权分开；本版 worker 无写入工具，不因计划批次完成或审批到达改变 owner/epoch。

## 开发仓库关联

用户明确要求关联或调整开发仓库时加载 task-repository；普通任务不强制 Git。关联是远端元数据，不是 checkout 或写入许可。门禁预检不排队、不转移所有权；只有明确启用并通过当前门禁的受管执行器才能实际写入。
